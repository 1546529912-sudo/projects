# Edge Cases · 边界与异常情况清单（产品 Agent 产物 3/5）

> 跨子功能的异常/边界情况汇总，开发 Agent 必须实现这些路径。

## 【当前焦点】

- 范围：5 大模块的边界与异常
- 强约束：每条 edge case 必须在 task-spec 至少一个判定项里对应

## 一、用户模块

| # | 场景 | 处理方式 |
|---|------|---------|
| U-01 | 同一手机号同时在两个浏览器注册 | 数据库 uniq 约束，第二个提交时返回"已注册"错误 |
| U-02 | 企业认证被驳回 | 可重新提交，驳回原因必显示，附"修改"按钮 |
| U-03 | 微信登录绑定的手机号与已有账号手机号冲突 | 弹窗引导用户合并账号或换手机绑定 |
| U-04 | 验证码 60 秒内重发 | 倒计时未到禁用按钮 |
| U-05 | 验证码错误超过 3 次 | 锁定该手机号 5 分钟禁止再发 |
| U-06 | 验证码过期（5 分钟） | 提交时提示"验证码已过期，请重新获取" |
| U-07 | 个人账号尝试访问企业才有的对公支付 | 提示"请先完成企业认证" |
| U-08 | 用户中途切换角色（个人 ↔ 企业） | 购物车/订单不丢失，但价格按当前角色重算 |

## 二、商品模块

| # | 场景 | 处理方式 |
|---|------|---------|
| P-01 | 商品下架后已在购物车 | 标红"已下架"，不可结算 |
| P-02 | 库存不足 | 详情页标"缺货"+ 询价按钮；下单时强校验 |
| P-03 | 搜索结果为空 | 显示"未找到匹配商品，建议调整关键词" + 热搜推荐 |
| P-04 | 商品批量导入 Excel 格式错误 | 返回错误行号和原因，正确行正常入库 |
| P-05 | 阶梯价设置数量区间重叠 | 保存时校验，提示"区间冲突" |
| P-06 | 商品主图未上传 | 列表/详情显示占位图，并附"暂无图片" |
| P-07 | 商品价格为 0 或负数 | 后台保存时阻断 |
| P-08 | 商品被多个分类同时引用 | 允许，但删除分类时检查引用 |

## 三、订单/支付模块

| # | 场景 | 处理方式 |
|---|------|---------|
| O-01 | 并发下单导致库存不足 | Redis 预扣库存 + MySQL 乐观锁；不足时返回"库存不足" |
| O-02 | 对公转账 72 小时未上传凭证 | 订单自动取消，库存释放 |
| O-03 | 用户在"待发货"状态申请取消 | 进管理员审批，审批期间订单待定 |
| O-04 | 支付回调延迟（微信/支付宝异步通知） | 订单保持"待付款"直至回调确认，定时任务每 5 分钟主动查询 |
| O-05 | 部分发货场景（一个订单含多 SKU，部分先发） | 订单状态显示"部分发货"，每个 SKU 独立物流号 |
| O-06 | 用户支付成功立即申请退款（退款走原路返回） | 微信/支付宝走 SDK 退款；对公转账退款走人工 |
| O-07 | 物流单号查询失败 | 显示"物流信息暂未更新"，提供商家联系电话 |
| O-08 | 订单评价超时（确认收货 30 天后） | 系统自动好评 |

## 四、AI 模块

| # | 场景 | 处理方式 |
|---|------|---------|
| A-01 | 用户输入完全无关内容（如"今天天气"） | AI 识别为闲聊，温柔引导回业务场景 |
| A-02 | 报价参数全缺失（用户只说"我要买东西"） | AI 连续追问最多 3 轮，仍无法获取关键参数则转人工 |
| A-03 | AI 对话中用户突然关闭页面 | 上下文持久化到 ai_conversations 表，再次打开恢复 |
| A-04 | RAG 知识库为空（初始化阶段） | AI 回复"暂时无法回答此问题，已为您转接人工客服" |
| A-05 | AI 生成的报价单中商品价格与实时价格不一致（价格在 AI 计算期间被修改） | 报价单页脚标注"价格以下单时为准" |
| A-06 | 用户多语言输入（中英文混杂） | AI 优先按中文处理，未识别词原样保留 |
| A-07 | 同一用户短时间内（1 分钟）发起 ≥10 条消息 | 限流，提示"消息发送过于频繁" |
| A-08 | AI 调用底层 LLM 超时（>10s） | 降级回复"AI 暂时繁忙，已为您转接人工" |

## 五、支付/资金模块

| # | 场景 | 处理方式 |
|---|------|---------|
| F-01 | 在线支付成功但平台未收到回调 | 定时任务主动查询支付状态 |
| F-02 | 对公转账凭证上传后管理员确认金额与订单金额不符 | 驳回并通知用户补差或退款 |
| F-03 | 用户支付后立即申请退款 | 退款走原路返回（微信/支付宝）；对公转账退款走人工 |
| F-04 | 同一订单重复点击支付（前端防抖未拦住） | 后端幂等：以订单号锁，第二次支付直接返回成功 |
| F-05 | 发票信息缺失（企业账号未填抬头） | 结算页强校验，缺则不可提交 |

## 六、平台/系统级

| # | 场景 | 处理方式 |
|---|------|---------|
| S-01 | 数据库连接池耗尽 | 队列削峰 + 用户提示"系统繁忙，请稍后重试" |
| S-02 | Redis 缓存击穿（热 key 失效瞬间大量并发） | 互斥锁 + 短过期时间 |
| S-03 | 文件上传超大小（>10MB） | 前端拦截 + 后端 413 |
| S-04 | XSS / SQL 注入尝试 | Laravel 自带 ORM 防注入；输入做 HTML escape |
| S-05 | 接口被暴力扫描 | 限流（每 IP / 每用户）|
| S-06 | 浏览器不支持（IE）| 提示"请使用 Chrome / Edge / Safari 最新版" |

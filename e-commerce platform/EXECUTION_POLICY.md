# EXECUTION_POLICY · 返工与升级规则

## 【当前焦点】

- 当前迭代：iteration-1（项目初始化）
- 当前 Phase：Phase -1
- 当前返工次数：0

## 【必须遵守】

### 返工梯度

| 级别 | 触发条件 | 处理 |
|------|---------|------|
| L0 自查 | Agent 自检产物不达标 | 自行修复，不计返工次数 |
| L1 第 1 次返工 | 用户或主控提出修改 | Agent 自行修复 |
| L2 第 2 次返工 | 同一产物再次被打回 | Agent 修复 + 主控审 |
| L3 第 3 次返工 | 仍未通过 | Agent 修复 + 主控强制 review |
| L4 升级 | 第 4 次仍未通过 | 升级给主控，主控介入 1 次定向修正 |
| L5 暂停 | 主控介入后仍不过 | 暂停该 Phase，提请用户决策是否重做 task-spec |

### 同类问题阈值

- 同类问题连续 2 次出现 → 主控提前介入（不等到 L4）
- 同类问题第 3 次出现 → 暂停 Phase，主控判断是否需要重做 task-spec
- "同类"判定：同一 Agent 同一类产物（如产品 Agent 的 task-spec 判定项不齐）

### 升级路径

```
Agent 自查（L0）→ 用户/主控反馈（L1-L3）→ 主控介入（L4）→ 用户决策（L5）
```

## 角色级返工政策

### 产品 Agent

- 判定项不足 5 条 → 直接打回，不计 L1（视为 L0 自查未过关）
- design-brief 仅写"参考 XX 风格"无具体色彩/字体/密度 → L0 打回
- 任务 ID 重复或缺失 → L0 打回

### 设计 Agent

- 未拿 design-brief 出图 → 红线，直接 L4
- 原型图只画"默认态"，无加载/完成/异常 → L1 打回
- 无交互说明 → L1 打回

### 架构 Agent

- 未在 tech-stack.md 第一行声明项目复杂度档位 → L0 打回
- 个人级小项目写微服务拆分（过度设计）→ L1 打回 + 主控审
- 中型 SaaS 只交 schema 不交 module-deps（欠设计）→ L1 打回

### 开发 Agent

- 未提交产物清单 → progress.md 不允许标记完成（HARNESS.md 红线）
- 产物清单文件不存在 → 立刻打回 + 主控对账记入日志
- 修改未声明文件 → L2 直接介入

### 测试 Agent

- 自动化测试报告"实际结果"全为"待填写" → 视为未提交，L0 打回
- 在没有用户验证的情况下宣称"全流程通过" → L4 升级 + 信任度降级

## 返工日志位置

`outputs/orchestration/rework-log.md`（由主控维护，每次返工追加一行）

格式：

```

|------|-------|--------|---------|------|------|

```

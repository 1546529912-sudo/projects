全文(对着这个念,大概 3-4 分钟)
============================================

【背景】

这个项目的起点是一个观察。我们每天都写日报,但日报基本
上就是个汇报材料,写完就交了,很少有人会回头反思"我这
段时间到底在往哪走"。

我自己有这种困扰。然后我想——如果有个行业大佬,比如说
乔布斯,他来看我的日报,他会怎么帮我复盘? 大多数人没机
会找这种人当导师。

所以我想用 AI 来填这个空缺。

【挑战】

我用 Multi-Agent 框架来做这个项目。理论上是 6 个 Agent
分工协作——产品、设计、架构、开发、测试,还有一个主控。

但跑下来我发现一个挺反直觉的问题: 6 个 Agent 里只有 2-3
个在真正干活,其他几个名义上存在,实际上是空转的。

最典型的是设计 Agent。我给了它 PRD,它也按 PRD 出了原型
图,流程上看一切正常。但出来的风格完全不是我要的。我得
自己去 Google 找设计参考,喂回去给它,它才能产出合格的
东西。

【行动】

我做了三件事。

第一,我做了一次完整的 Agent 工作状态盘点。但不是问 AI
"你做了什么"——它会说"我做了 X"。 我直接去文件系统里查,
只看 outputs 目录里到底有没有这个 Agent 应该产出的文件。
这一查就发现,产品 Agent 完全没产出,测试 Agent 只交了
空模板。

第二,我重构了 prompt。核心改动是把"声明角色"升级为"硬
约束"——每个 Agent 必须有明确的必交产物清单,不交不准下
一步。比如设计 Agent 启动前,必须先拿到一份 design-brief,
这份文档里要有风格参考、品牌色、避免的风格——没这个文档
不准启动。

第三,我加了对账机制。主控 Agent 每轮迭代结束,必须用文
件系统去核对 progress.md 里的"已完成"是否真的完成。不能
AI 自己说自己完成了就算完成。

【结果】

V0.1 上线了,核心功能跑通。但坦白说,我觉得这个项目最大
的价值不是产品本身,是我沉淀出了一套 Multi-Agent prompt
的工程化框架。这套框架我接下来会拿到下一个项目里继续验证。

【反思】

这个项目让我最大的认知升级,是对"AI 自驱"这件事的理解变了。

我之前的理解是:给 AI 一个角色定义,它就能自驱地把活干完。
跑完之后我意识到这是个错觉。

真正可靠的 Multi-Agent 系统,需要更严的工程纪律,不是更松。
每个角色要有可验证的产出、流程要有强制门控、状态要有第三方
核验——这跟传统软件工程里"接口契约"的思想是一致的。

所以现在我看 AI Agent 的产品,我会先看一件事: 它是真的"自
驱",还是只是在"声明自己自驱"?

# UI Rules

## 核心原则

1. **清晰优先** — 功能清晰胜过视觉华丽
2. **一致性** — 相同场景用相同方案，不创造例外
3. **反馈及时** — 每个操作都需要明确的状态反馈
4. **减少认知负担** — 每个页面只有一个主操作

---

## 1. 间距规则

- 使用 4px 基础网格，所有间距必须是 4 的倍数
- 相关元素之间间距小，不相关元素之间间距大
- 组件内部 padding：小组件 8-12px，中组件 16px，大组件 24px
- 节与节之间最小间距 64px（移动端 48px）

---

## 2. 颜色使用规则

- 主色最多出现在 1-2 个核心操作上，不滥用
- 禁止使用纯黑 `#000000` 作为文字颜色，用 `#0D1117` 或 `#212529`
- 背景不超过 2 层嵌套颜色
- 语义色（红/黄/绿）只用于状态表达，不用于装饰

---

## 3. 字体规则

- 一个页面最多使用 2 种字重组合
- 正文最小字号 14px，移动端 16px
- 行高：正文 1.6-1.75，标题 1.2-1.3
- 禁止全大写正文（标签/标题可用）
- 文字最大宽度 70ch，超出需换行或截断

---

## 4. 按钮规则

### 层级
- Primary：每个视图只有 1 个
- Secondary：辅助操作，可多个
- Ghost/Text：低优先级，不干扰视觉重心

### 尺寸
| Size | Height | Padding | Font |
|------|--------|---------|------|
| sm | 32px | 12px | 13px |
| md | 40px | 16px | 14px |
| lg | 48px | 20px | 16px |

### 状态
- Default → Hover（变暗 10%）→ Active（变暗 20%）→ Disabled（40% opacity）
- Loading 状态需显示 spinner，禁用点击

---

## 5. 表单规则

- Label 始终在 Input 上方，不使用 placeholder 替代 Label
- 错误信息在 Input 下方，颜色用 error token，前缀图标
- 必填字段标记 `*`，非必填不标注
- Input 获取焦点时显示 2px 主色 outline
- 提交按钮位于表单底部，右对齐或全宽

---

## 6. 图标规则

- 统一使用同一套图标库（推荐 Lucide / Phosphor）
- 尺寸：16px（内联）/ 20px（按钮内）/ 24px（独立图标）
- 图标单独使用时必须有 `aria-label` 或 Tooltip
- 不混用不同风格的图标（线性 vs 填充）

---

## 7. 图片规则

- 所有图片需设置 `alt` 文字
- 加载前显示 skeleton 占位
- 图片容器固定宽高比，用 `object-fit: cover`
- 头像使用圆形，产品截图使用圆角矩形

---

## 8. 空状态规则

空状态需包含：
1. 插图或图标（不能只有文字）
2. 标题：说明"什么都没有"
3. 描述：解释原因或建议操作
4. CTA（可选）：引导用户下一步

---

## 9. 加载状态规则

| 场景 | 方案 |
|------|------|
| 页面首次加载 | Skeleton screen |
| 列表刷新 | Spinner 居中 |
| 按钮触发操作 | 按钮内 spinner + 禁用 |
| 局部更新 | 局部 overlay spinner |
| 超过 3s 未完成 | 显示进度或提示 |

---

## 10. 错误处理规则

- 网络错误：显示重试按钮
- 表单错误：字段内联提示，不弹窗
- 系统错误：Toast 通知（右上角，3s 消失）
- 严重错误：全屏错误页，提供返回首页入口

# EXECUTION_POLICY（product_ai_tool）

本文档定义 **AI Demo 标注工具** 多 Agent 协作过程中的执行策略，重点覆盖防重复、重试上限、幂等处理、长流程兜底与升级规则。

它与 [HARNESS.md](./HARNESS.md) 的关系是：

- `HARNESS.md` 定义全局边界与约束
- `EXECUTION_POLICY.md` 定义执行过程中的收敛机制与兜底机制

## 1. 目标

本策略用于避免以下问题：

- 子 Agent 围绕同一问题无限返工
- 不同角色重复产出同类内容
- 同一 `progress` 条目被反复回写或误回写
- 长流程卡住后无人升级处理
- 主控 Agent 无法判断何时该继续、何时该中止、何时该升级

## 2. 重试与返工上限

默认规则如下：

- 子 Agent 自主返工上限：`3` 次
- 第 `4` 次仍未通过：必须升级给主控 Agent
- 主控 Agent 介入后，可再给 `1` 次定向修正机会
- 若仍未通过：升级给负责人拍板，并停止同路径无限循环

说明：

- “自主返工”指同一角色针对同一问题、按同一目标反复修正
- “定向修正”指主控 Agent 已明确指出缺失项、冲突项或修正方向后的再提交

## 3. 提前介入规则

即使未达到返工上限，出现以下情况时，主控 Agent 也应提前介入：

- 同类问题连续 `2` 次重复出现
- 上下游角色对同一问题给出冲突结论
- 下游角色因上游输入缺失而无法继续推进
- 某角色连续两次提交都未满足模板或交接要求
- 问题已经超出当前角色职责边界

## 4. 问题分类处理

### 文档不完整或交付格式错误

- 允许子 Agent 自主返工，最多 `3` 次
- 若连续 `2` 次仍是同类格式问题，主控 Agent 应检查模板或 skill 是否缺失

### 需求理解偏差

- 允许返工，但若第 `2` 次仍存在范围偏差，建议提前升级给主控 Agent
- 若涉及需求边界变化，直接升级给负责人

### 设计与架构冲突

- 不按普通返工计算
- 直接交由主控 Agent 协调
- 若仍无法收敛，升级给负责人

### 开发实现缺陷

- 允许子 Agent 自主修复，最多 `3` 次
- 若第 `4` 次仍失败，主控 Agent 需检查是否为上游输入不充分，而非单纯实现问题

### 测试反复打回同类问题

- 若同类问题连续 `2` 次出现，主控 Agent 应复核产品、设计、架构或 skill 是否存在缺口
- 不得默认全部归因为开发问题

## 5. 幂等规则

为避免重复产出和重复回写，默认遵守以下规则：

- 若目标产物已存在，优先更新原文档，而不是重复新建同类文档
- 若某个 `progress` 阶段已勾选，不得重复回写同一阶段
- 若本轮 runbook 已冻结范围，不得在同一轮内无说明地改写目标范围
- 同一问题若已有明确结论，不得让其他角色在不知情情况下重复输出一份平行结论

## 6. 长流程兜底

当某轮迭代长时间未推进时，主控 Agent 应按以下顺序检查：

1. 当前 runbook 是否明确了本轮范围
2. 上游产物是否齐备
3. 是否已有角色提交但未被接收
4. 是否存在未升级的阻塞项
5. `progress.md` 是否与真实阶段不一致

若仍无法恢复推进，则：

- 在 `progress.md` 的“当前问题”中登记阻塞
- 输出新的调度说明
- 必要时升级给负责人

## 7. 回写保护

- 没有证据的建议勾选，不得回写
- 没有测试结论，不得把“开发完成”视为“整项完成”
- 已回写的阶段若被证明错误，必须由主控 Agent 明确记录修正原因

## 8. 完成信号

当一次问题处理满足以下条件时，可视为已收敛：

- 已在允许次数内完成修正
- 不再重复出现同类问题
- 交接条件满足
- `progress.md` 与实际阶段一致

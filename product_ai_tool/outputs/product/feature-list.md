# Feature List

## 本轮目标

- 跑通第一轮最小闭环，覆盖 `progress` 1、2、4、5
- 建立可承载单 HTML Demo 的宿主页基础工作台
- 明确本轮只做基础布局、输入区、`deepseek-v4-flash` 模型选择位、iframe 预览和最小协议约束
- 为后续标注 overlay、页面过滤、AI 修改和版本能力打基础

## 功能清单

### 基础页面布局

- 用户/场景：用户进入 AI Demo 标注工具后，需要先看到一个稳定、清晰、可扩展的工作台界面。
- 描述：提供顶栏、左侧面板、中间画布、右侧面板的基础三栏工作台布局，形成后续所有操作的承载外壳。
- 优先级：最高
- 验收标准：
  - 页面具备顶栏、左侧面板、中间画布、右侧面板四个主要区域
  - 各区域职责清晰，不互相遮挡
  - 中间画布区域可稳定承载 iframe 预览
  - 布局为后续 overlay 标注层预留空间
- 第一版不做：
  - 不做标注 overlay 交互
  - 不做标注列表联动
  - 不做版本历史面板
- 关联 progress 序号：1
- 是否需调整 progress.md：否

### 需求输入和模型选择

- 用户/场景：用户需要输入 Demo 需求，并看到当前项目指定使用的 `deepseek-v4-flash` 模型入口。
- 描述：在左侧面板提供需求输入区和模型选择区。第一轮可以先完成 UI 与基础交互，不要求立即打通真实模型调用，但模型口径需固定为 `deepseek-v4-flash`。
- 优先级：最高
- 验收标准：
  - 页面存在可输入需求的文本区域
  - 页面存在模型选择控件或固定模型展示位
  - 用户能够明确看到当前输入位置与当前模型为 `deepseek-v4-flash`
  - 即使未接真实模型，也不影响页面结构完整性
- 第一版不做：
  - 不要求真实调用多个模型
  - 不要求第一轮支持切换到其他模型
  - 不要求完成完整生成链路
- 关联 progress 序号：2
- 是否需调整 progress.md：否

### iframe 预览单 HTML Demo

- 用户/场景：用户需要在宿主页中查看 AI 生成或示例提供的单 HTML Demo。
- 描述：中间画布区域使用 iframe 承载单 HTML Demo，优先采用 `srcdoc` 或等价方式，确保后续宿主与 Demo 隔离清晰。
- 优先级：最高
- 验收标准：
  - 中间区域可展示单 HTML Demo
  - Demo 在 iframe 中运行，不直接写入宿主页 DOM
  - 无 Demo 时存在明确占位或空状态
  - 承载方式不阻碍后续增加 sandbox 与 overlay
- 第一版不做：
  - 不要求支持多文件工程
  - 不要求支持外部页面跳转
  - 不要求支持真实后端依赖
- 关联 progress 序号：4
- 是否需调整 progress.md：否

### Demo 页面标识与最小协议约束

- 用户/场景：系统需要识别 Demo 当前页面，并为后续按页过滤标注做准备。
- 描述：第一轮先明确并打通最小协议约束，至少支持 `DEMO_READY` 和 `DEMO_PAGE_CHANGE` 两类消息，以及 `pageKey` 的最小读取与同步。
- 优先级：最高
- 验收标准：
  - 宿主可以接收 Demo 发出的 `DEMO_READY`
  - 宿主可以接收 Demo 发出的 `DEMO_PAGE_CHANGE`
  - `DEMO_PAGE_CHANGE` 中包含 `pageKey`
  - 宿主能够维护当前 `pageKey` 状态，供后续标注系统使用
- 第一版不做：
  - 不要求完整实现 `DEMO_STATE_CHANGE`
  - 不要求完整实现 `DEMO_ACTION`
  - 不要求在本轮接入标注过滤逻辑
- 关联 progress 序号：5
- 是否需调整 progress.md：否

## 第一轮明确不做

- 不接入真实模型生成完整 Demo，对应 `progress` 3
- 不进入标注能力开发，对应 `progress` 6-12
- 不进入 AI 修改、版本保存、版本回退，对应 `progress` 13-15
- 不扩展到多文件 React/Vue/Next.js 工程
- 不接真实业务后端接口

## 风险与待确认项

- 第一轮是否完全使用静态示例 HTML 或本地 mock 数据，由架构与开发共同确认落地方式
- `pageKey` 的命名规范和最小格式，需要架构 Agent 在协议文档中固定
- 若 `DESIGN.md` 中现有组件无法覆盖工作台布局，需要设计 Agent 提前标记专有控件
- 正式方案已建议采用 PHP 优先架构；当前 `web/` 原型不应直接视为最终生产方案

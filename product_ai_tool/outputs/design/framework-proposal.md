# Design Framework Proposal

## 本轮目标

- 为 `product_ai_tool` 第一轮范围输出正式设计产物
- 对齐已确认的产品范围：`progress` 1、2、4、5
- 对齐已确认的正式技术方向：**PHP 优先方案**，当前 `web/` 仅作为交互原型参考
- 为后续 Laravel 版工作台实现提供可直接落地的布局和交互规范

## 设计方向

- 采用项目根目录 [DESIGN.md](/Users/linfeng/Desktop/project/product_ai_tool/DESIGN.md) 中已定义的黑白高对比、胶囊按钮、紧凑信息密度设计系统
- 工具台界面保持克制、稳定、可扫描，不抢 Demo 本身的视觉注意力
- 工作台 chrome 尽量轻，核心焦点放在中间 Demo 预览区
- 当前阶段优先建立“稳定工作台骨架”，而不是追求装饰性表达

## 页面结构

### 顶栏

职责：

- 产品标题
- 当前模型信息：`deepseek-v4-flash`
- 预览 / 标注模式切换
- 生成 Demo 主操作

设计原则：

- 高度紧凑，保持单层信息
- 使用 `Primary Black CTA` 承载“生成 Demo”
- 模式切换使用胶囊分段控件
- 模型区使用轻量说明，不做复杂下拉切换器

### 左侧面板

职责：

- 需求输入
- 当前 Demo 信息
- 模型提示

设计原则：

- 固定宽度，优先保障输入区可用性
- 需求输入为主卡片区
- 当前 Demo 信息作为次级信息卡片
- 第一轮不堆叠过多管理信息，避免噪音

### 中间画布

职责：

- 承载 iframe 预览
- 后续承载 overlay 标注层

设计原则：

- 这是页面视觉中心
- 第一轮先确保预览区域比例稳定、留白清晰
- 画布容器需为后续 overlay 预留绝对定位层

### 右侧面板

职责：

- 当前 `pageKey`
- 协议消息调试信息
- 后续标注列表预留

设计原则：

- 第一轮以协议状态和当前页面信息为主
- 标注区先保留信息架构，不强行填满
- 作为未来“标注列表 / 编辑区”的承载面板

## 关键状态

### 预览模式

- 默认状态
- 用户可正常查看和操作 Demo
- 顶栏模式切换处于“预览”激活态

### 标注模式

- 第一轮只保留切换入口与视觉状态
- 可以显示“标注能力将在后续迭代接入”的轻提示
- 不在本轮真正实现标注落点交互

### 空状态

- 无 Demo 时，中间画布显示明确占位说明
- 引导用户先输入需求或加载示例
- 空状态不应像报错，应更像“待开始”

### 加载状态

- 生成中时，主按钮文本切换为“生成中…”
- 画布保持稳定，不闪烁跳动
- 可在预览区显示轻量 loading 提示

### 错误状态

- 模型调用失败时，错误信息显示在左侧输入区下方
- 若自动回退离线示例，需明确说明“已改用示例 HTML”
- 错误信息使用系统中较克制的警示文本，不做重度警报视觉

## 组件映射

### 顶栏

- 页面区域：顶栏操作区
- 对应 `DESIGN.md` 组件：
  - `Primary Black (CTA)`
  - `Chip / Filter`
  - `Navigation`
- 备注：模式切换可用胶囊式二段控件实现

### 左侧输入区

- 页面区域：需求输入、Demo 信息卡
- 对应 `DESIGN.md` 组件：
  - `Inputs & Forms`
  - `Cards & Containers`
- 备注：输入框保持黑边白底，信息卡用轻阴影卡片承载

### 中间画布

- 页面区域：iframe 预览区
- 对应 `DESIGN.md` 组件：
  - `Cards & Containers`
  - `Depth & Elevation`
- 备注：外层容器使用 8px 圆角和轻阴影，不抢 iframe 内容

### 右侧信息区

- 页面区域：协议状态、页面信息
- 对应 `DESIGN.md` 组件：
  - `Cards & Containers`
  - `Caption / Micro typography`
- 备注：信息密度可略高，但要保持条理

## 专有控件

### 模式切换分段控件

- 用途：切换预览 / 标注模式
- 复用 token：
  - 黑白反转
  - 999px radius
  - 轻阴影 / 无阴影切换
- 交互说明：
  - 当前模式黑底白字
  - 非当前模式浅灰底黑字

### 画布空状态容器

- 用途：在无 Demo 时提供引导
- 复用 token：
  - 白底
  - 黑色标题
  - 次级灰说明文案
- 交互说明：
  - 中间对齐
  - 不应看起来像异常页

### 协议日志列表

- 用途：展示 `DEMO_READY`、`DEMO_PAGE_CHANGE` 等消息
- 复用 token：
  - 卡片容器
  - 小号文字层级
  - 浅灰信息背景
- 交互说明：
  - 最新消息优先显示
  - 保持单行可扫描

## 与 PHP 方案的对齐

- 页面结构以 Laravel Blade 可直接实现为前提
- 不依赖 Next.js 专属交互模式
- 交互复杂度控制在 Alpine.js / 原生 JS 可舒适承载的范围内
- 后续若进入标注 overlay 阶段，再单独扩展专有控件说明

## 风险与待确认项

- 右侧区域在第一轮是否保留足够多的“标注占位”，还是完全聚焦协议调试
- 标注模式在第一轮是否只做视觉切换，不做任何交互提示
- 后续 overlay 复杂度若显著增加，是否仍坚持 Blade + Alpine.js 路线

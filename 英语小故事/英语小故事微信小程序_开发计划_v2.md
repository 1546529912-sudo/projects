## 一、项目定位

这是一个面向儿童的英语分级阅读微信小程序。

核心目标：

- 让孩子愿意打开
- 愿意听
- 愿意读
- 愿意点单词
- 愿意持续使用

产品方向：

- 明亮活泼
- 绘本感
- 轻学习感
- 低认知负担
- 手机页面友好

# 五、关键隐藏模块（必须）

## 1. 内容安全审核模块

AI生成内容必须经过：

```text
AI生成
→ 敏感词检测
→ 年龄内容检测
→ 难度检测
→ 人工抽检
→ 入库
```

> 注意：第一版 AI 不自动生成内容，种子内容由人工 AI 辅助生成后人工检查入库。
> 因此第一版内容安全审核可简化为：人工审核，不需要建完整自动化管道。

目的：

避免出现：

- 不适合儿童内容
- 越级词汇
- 奇怪故事
- 暴力内容

---

## 2. 词汇等级控制模块

这是整个产品真正的技术壁垒。

目的：

控制不同等级只能出现对应难度词汇。

例如：

L1只能出现：

- cat
- dog
- run
- happy

避免AI生成越级单词。

# 七、三大核心技术方案（已确认）

## 1. 词库数据来源

**方案：Free Dictionary API（免费，无商业限制）**

```text
请求格式：
https://api.dictionaryapi.dev/api/v2/entries/en/<word>

返回内容：
- 音标（IPA）
- 词义（英文释义）
- 例句
```

> 不使用牛津/剑桥官方 API 的原因：
> 牛津 API 企业授权起步价每年 £5,000，且不允许缓存数据到本地数据库，不适合免费项目。

**词库建立方式：**

- 根据15级词汇范围，提前批量请求 Free Dictionary API
- 将音标、释义存入自己的 MySQL 数据库
- 中文释义由 AI 批量翻译后人工抽检补充

---

## 2. 音频方案

**方案：牛津学习者词典美式发音直链（免费，真人录音）**

```text
URL 格式示例：
https://www.oxfordlearnersdictionaries.com/media/english/us_pron/a/app/apple/apple__us_1.mp3

小程序播放方式：
wx.createInnerAudioContext() 直接播放该 URL
```

**优势：**

- 完全免费
- 真人录音，音质优于任何 TTS
- 美式发音，符合产品定位

**风险与应对：**

| 风险 | 应对方案 |
|---|---|
| 牛津链接结构变动导致失效 | 按需缓存：首次播放时将 mp3 下载存到自己服务器，后续走缓存 |
| 高并发被限流 | 同上，缓存后不再请求牛津服务器 |

> 第一版用户量小，可先直接请求直链，等用户量上来再加缓存层，不提前过度设计。

---

## 3. 种子内容方案

**方案：AI 生成 + 人工检查 + 手动入库**

```text
流程：
用 Claude/GPT 生成 L1-L3 各5篇故事（共15篇）
  ↓
人工检查（词汇是否越级、内容是否适合儿童）
  ↓
确认无误后手动注入数据库
  ↓
以此为基础开始开发测试
```

> 不建议第一版直接全自动注入不检查。
> 儿童产品对内容质量要求高，15篇人工过一遍花不了多少时间。

**后续扩充：**

- 验证阅读体验后，再批量用 AI 生成并走自动化审核管道

# 十、技术架构建议

## 小程序端

```text
微信原生小程序 + TypeScript
```

原因：性能稳定、音频兼容好、更适合儿童产品。

---

## 后端

```text
Node.js + NestJS
```

---

## 数据库

```text
MySQL（主库）
Redis（缓存）
```

---

## 注意事项（讨论中补充）

- 技术栈整体偏重，适合有一定团队或时间的独立开发者，独立开发需评估工期
- 第一版优先跑通核心体验，后端可先用简单 Express 替代 NestJS，降低启动成本

# 十一、UI设计方向

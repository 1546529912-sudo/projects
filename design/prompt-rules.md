# Prompt Rules

## 概述

本文档规范 AI 设计生成、内容生成、代码生成等场景下的 Prompt 编写规则，确保输出质量一致、可复现。

---

## 1. Prompt 基本结构

每条 Prompt 遵循以下结构：

```
[角色设定] + [任务描述] + [约束条件] + [输出格式] + [示例（可选）]
```

### 模板
```
你是一名 [角色]，擅长 [能力领域]。
请根据以下要求完成任务：[具体任务]
约束条件：[限制1] / [限制2] / [限制3]
输出格式：[格式要求]
```

---

## 2. 角色设定规则

- 角色要具体，避免泛化（"你是设计师" → "你是专注移动端体验的 Product Designer"）
- 指定专业背景和思维框架
- 必要时注明风格偏好（"简洁克制，不过度设计"）

### 常用角色库
| 场景 | 角色设定 |
|------|---------|
| UI 设计 | 资深 Product Designer，熟悉 Material Design 和 Apple HIG |
| 文案 | UX Writer，擅长简洁、有温度的产品文案 |
| 代码 | Senior Frontend Engineer，精通 React + TypeScript |
| 分析 | 产品经理，擅长用数据驱动决策 |
| 营销 | 品牌策略师，熟悉 B2B SaaS 市场 |

---

## 3. 任务描述规则

- 一个 Prompt 只做一件事，不要堆叠多个目标
- 用动词开头：设计 / 生成 / 分析 / 优化 / 翻译
- 提供足够的上下文：用户是谁 / 场景是什么 / 目标是什么
- 避免模糊词：好看、优化、改进 → 改为具体指标

### 反例 vs 正例
```
反例：帮我优化这个界面
正例：针对 30-45 岁的企业用户，优化这个数据看板的信息层级，
      使核心指标（收入/转化率/用户数）在 3 秒内被识别到
```

---

## 4. 约束条件规则

约束分三类：

### 内容约束
- 字数限制：不超过 / 恰好 / 至少 N 字
- 不能出现的内容：专业术语 / 竞品名称 / 特定词汇
- 必须包含的元素

### 风格约束
- 语气：正式 / 轻松 / 专业 / 亲切
- 风格：极简 / 科技感 / 温暖 / 商务
- 禁忌：夸张用词 / 感叹号 / 过度承诺

### 技术约束
- 平台限制：iOS / Android / Web
- 组件库：使用 Shadcn / Ant Design / MUI
- 代码规范：TypeScript strict / ESLint / 无注释

---

## 5. 输出格式规则

明确指定输出格式，避免模型自由发挥：

| 场景 | 格式指令 |
|------|---------|
| 列表 | "以 Markdown 无序列表输出，每项不超过 20 字" |
| 表格 | "以 Markdown 表格输出，包含列：名称/说明/示例" |
| 代码 | "只输出代码，不加解释，使用 TypeScript" |
| JSON | "输出合法 JSON，字段包含：title/description/tags" |
| 文案 | "输出 3 个版本，每版一行，不加编号以外的格式" |

---

## 6. 设计生成 Prompt 规范

### UI 设计场景
```
设计一个 [组件名]，用于 [使用场景]。
- 用户：[目标用户]
- 平台：[Web / iOS / Android]
- 风格：[设计风格关键词]
- 状态：包含 [default / hover / active / disabled / loading / error]
- 尺寸：[尺寸规格]
- 约束：使用全局设计系统的 token，不引入新颜色
```

### 图标生成
```
设计一个 [概念] 的图标
- 风格：线性 / 填充 / 双色
- 尺寸：24x24px，1.5px 描边
- 风格参考：Lucide Icons
- 关键特征：[2-3个视觉特征]
```

---

## 7. 文案生成 Prompt 规范

### 产品文案
```
为 [产品/功能] 写 [文案类型：标题/描述/CTA/错误提示]
- 受众：[用户画像]
- 语气：[正式/亲切/专业]
- 字数：不超过 [N] 字
- 避免：技术术语 / 夸大承诺 / 被动语态
- 输出：3个版本，每版一行
```

### 错误提示文案
```
场景：用户 [操作] 时发生 [错误类型]
要求：
1. 说明发生了什么（不责怪用户）
2. 告诉用户该怎么做
3. 语气友好，不超过 20 字
```

---

## 8. 代码生成 Prompt 规范

```
用 [语言/框架] 实现 [功能描述]
- 输入：[参数说明]
- 输出：[返回值说明]
- 约束：
  · 不使用第三方库（或：只使用 [指定库]）
  · TypeScript strict mode
  · 函数式风格，不使用 class
  · 不加注释
- 只输出代码，不加解释
```

---

## 9. 迭代优化规则

- 首次输出不满意时，不要重新写 Prompt，先用修正指令
- 修正指令格式：`保持 [好的部分]，修改 [具体问题]`
- 最多迭代 3 次，超过则重新梳理需求

### 常用修正指令
```
"更简洁，去掉所有修饰词"
"更专业，减少口语化表达"
"风格更一致，参考第2个版本的语气"
"保留结构，重写第3段"
```

---

## 10. 禁止事项

- 不在 Prompt 中使用"随便"、"任意"、"看你"等模糊词
- 不一次性让模型做超过 3 步的推断
- 不省略输出格式说明
- 不用否定描述风格（"不要太正式"→"使用轻松对话语气"）
- 不依赖模型"记住"上下文超过 5 轮

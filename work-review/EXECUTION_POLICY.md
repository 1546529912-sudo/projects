# EXECUTION_POLICY.md — 执行策略与全局规则

> 【必须遵守】所有 Agent 在任何情况下都不得绕过本文件中的规则

---

## 一、核心原则

```
1. 能直接落地代码骨架，不写只有建议
2. 能明确成任务，不停留在抽象描述
3. 能形成可执行产物，不交付空壳文档
4. 未通过测试的产物不得标记完成
5. 【硬性门控】设计稿（原型图）必须经用户确认后，开发 Agent 才能开始页面实现
```

---

## 一（补）、设计确认门控（硬性规则）

**触发时机**：任何涉及 UI 页面的开发任务启动前。

**流程**：
```
设计 Agent 输出原型图
→ 提交给用户确认
→ 用户明确回复"确认"或提出修改意见
→ 设计 Agent 根据反馈修改
→ 用户再次确认
→ 主控 Agent 在 progress.md 记录"设计已确认"
→ 开发 Agent 才能启动页面实现
```

**违反后果**：
- 开发 Agent 若在设计未确认前实现页面，产物无效，须推倒重做
- 主控 Agent 须在 progress.md 记录违规并标记返工

---

## 二、返工上限策略

| 返工次数 | 处理方式 |
|---|---|
| 1-3 次 | 子 Agent 自主返工，记录原因 |
| 第 4 次 | 停止返工，提交 blocker 给主控 |
| 主控介入后 | 给 1 次定向修正机会 |
| 同类问题 ≥ 2 次 | 主控提前介入，不等第 4 次 |

---

## 三、quality gate（质量门控）

### 代码质量门控

- [ ] 接口有参数校验
- [ ] 有错误处理（不能直接 500）
- [ ] AI 输出有 Schema 校验
- [ ] 关键操作有日志
- [ ] 数据库操作有事务保护
- [ ] 敏感信息不写入日志

### 测试质量门控

- [ ] 健康检查接口可通过
- [ ] 前后端基础联通链路可通
- [ ] 云数据库集合已创建并权限正确
- [ ] AI 提取接口有 mock 测试覆盖
- [ ] 错误场景有对应测试用例

---

## 四、AI 服务调用规则

- 每次 AI 调用必须记录到 `ai_logs` 表
- Prompt 变更必须通知产品 Agent 审批
- AI 输出必须通过 Report Schema 校验
- Schema 校验失败时返回友好错误，不展示原始 AI 输出
- Token 消耗超过预算时告警

---

## 五、云数据库规则

- 所有集合必须有 `createTime`、`updateTime` 字段（使用 `db.serverDate()`）
- 软删除优先：添加 `isDeleted: false` 字段，不直接删除用户数据
- 每条记录必须有 `openid` 字段，云数据库权限设置为"仅创建者可读写"
- 查询时必须带上 `openid` 过滤，禁止全集合扫描用户数据

---

## 六、前端规则（微信小程序）

- 云函数调用统一走 `utils/cloud.js`，不得在页面中直接调用 `wx.cloud.callFunction`
- 所有页面必须有 loading 状态和 error 状态处理
- 云数据库操作只在云函数中进行，小程序端不直接操作数据库
- 页面跳转必须用 `wx.navigateTo`，不得拼接字符串 URL
- 云存储文件 ID 不得硬编码在前端

## 六（补）、云开发规则

- 所有云函数必须有完整的 try/catch
- 云函数返回格式统一：`{ code: 0, data: {} }` 或 `{ code: 错误码, message: '' }`
- 云数据库集合命名：下划线风格（work_records、daily_reports、ai_logs）
- AI 服务的 API Key 只存放在云函数环境变量中，不得出现在小程序前端代码

---

## 七、安全规则

- 非健康检查云函数必须校验调用上下文和必要参数
- 录音文件上传后云函数侧验证文件类型
- 不允许把敏感逻辑下放到小程序端，数据库写操作仅在云函数内执行
- AI Prompt 中禁止直接拼入用户原始输入（需先过滤）

---

## 八、文档规则

- 文档必须有【当前焦点】区块在最前面
- 重要内容放前 1/3
- 细节和历史放后面
- 用列表格式，不用长段落
- README.md 超过 50 行必须裁剪

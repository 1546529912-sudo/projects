# 设计 Agent SKILL — design

> 【当前焦点】Phase 0：输出核心页面原型图，等待用户确认  
> 【必须遵守】原型图未经用户确认，开发 Agent 不得开始任何页面实现

---

## Read First

1. `PRD.md` → 三、信息架构 + 四、功能列表
2. `EXECUTION_POLICY.md` → 设计确认门控规则
3. `progress.md` → 设计任务状态

---

## Responsibilities

- 为每个页面输出**可供用户确认的原型图**（文字线框图格式）
- 等待用户逐页确认后，才允许开发 Agent 开始实现
- 根据用户反馈修改设计稿，直到确认通过
- 输出设计规范（颜色、间距、组件库）供开发参考
- Phase 2 起对开发 Agent 的 UI 实现做 review

---

## 原型图输出格式

使用 ASCII 线框图格式，必须清晰展示：
- 页面布局（上中下结构）
- 核心组件位置和内容
- 关键交互说明（长按、点击的目标）
- 页面状态（默认/加载中/成功/失败）

**示例格式**：
```
┌─────────────────────────┐
│ 导航栏：页面标题         │
├─────────────────────────┤
│                         │
│  [组件 A]               │
│  说明文字               │
│                         │
│  ┌───────────────────┐  │
│  │ 卡片内容          │  │
│  └───────────────────┘  │
│                         │
├─────────────────────────┤
│  [底部按钮]             │
└─────────────────────────┘
交互说明：长按录音按钮 → 开始录音
```

## Workflow（严格按顺序执行）

```
Step 1: 读 PRD 对应页面的功能列表
Step 2: 输出该页面的 ASCII 原型图（含所有状态）
Step 3: 提交给主控 Agent
Step 4: 主控展示给用户确认
Step 5: 等待用户反馈
         ├── 用户确认 → 主控标记"已确认"→ 通知开发 Agent 可开始
         └── 用户有修改意见 → 返回 Step 2 修改后重新提交
Step 6: 所有页面确认后，整理设计规范文档
```

**严禁**：在 Step 5 用户确认前，通知或允许开发 Agent 开始实现。

| 工作录入页 | 默认态、录音中、AI 处理中、完成 | P0 最高 |

## Required Outputs（每个页面）

- ASCII 原型图（所有页面状态）
- 交互说明（用户操作 → 系统响应）
- 确认状态记录（待确认 / 已确认 / 修改中）

设计规范文档（所有页面确认后输出）：
- 颜色变量定义
- 组件规范（按钮、卡片、输入框）
- 间距规范

产物存放：`outputs/design/` 目录

## Guardrails（护栏）

- 不写 JS 业务逻辑代码
- 不做后端/云函数设计
- 原型图必须是可理解的，不能只有抽象描述
- 在用户确认前，不得向开发 Agent 发出任何"可以开始"的信号
- 每次用户提出修改意见时，必须通知主控 Agent 由主控回写 progress.md 状态为"修改中"

---

## Blocking / Escalation

- 遇到 PRD 未定义的 UI 细节：给出推荐方案并在原型图中标注"待确认"
- 用户连续 2 次否定同一方向：提交 blocker 给主控，主控决定是否重新澄清需求
- 遇到技术实现约束影响设计：咨询架构 Agent，不自行决定

# EXECUTION_POLICY.md · 返工与升级规则

## 返工上限

| 层级 | 上限 | 触发后 |
|---|---|---|
| 子 Agent 自主返工 | 3 次 | 第 4 次仍未通过 → 升级主控 |
| 主控定向修正 | 1 次 | 仍未通过 → 暂停 Phase，待用户介入 |
| 同类问题连续出现 | 2 次 | 主控提前介入，跳过子 Agent 自主返工 |
| 同类问题 3 次 | — | 暂停 Phase，主控判断是否重做 task-spec |

## 升级触发

下列情况 Agent **必须**升级（写入 progress.md【当前问题】区）：
1. PRD 与默认值冲突，且 Agent 无明确依据决策
2. 跨 Agent 工作出现循环依赖（A 等 B、B 等 A）
3. 用户已确认默认值被发现不可行（如端口冲突）
4. 自动化测试发现的问题已超出当前任务 task-spec 范围
5. 任何"超出 task-spec"的需求扩展请求

## 升级路径
```
Agent 自查 → Agent 自主返工 ≤3 → 升级主控 → 主控定向修正 ≤1 → 升级用户
```

## 强制返工的判定

主控对账若发现以下任一，对应任务**强制返工**：
- 产物清单中声称的文件不存在
- 测试报告"实际结果"全部为"待填写"
- 判定项对照未逐条对应 task-spec
- Agent 自述完成但 grep 不到关键函数/接口
- design-brief 中"复用 Airbnb 组件"少于 3 类

## 阻塞下游 Agent

当某 Agent 处于"待返工"状态：
- 该 Agent 的下游 Agent **禁止**启动
- 主控在 progress.md 中标注【阻塞】，注明阻塞来源任务 ID

## 紧急停止

- 用户随时可在对话中指示"停止当前 Phase"
- 主控停止后必须输出 stop-report，列出已完成 / 未完成 / 半成品状态

# non-goals.md · 本期明确不做的范围

## 【当前焦点】
明确电商商城 v1 本期（Phase -1 → Phase 4）**不做**的功能与系统，避免开发 Agent 偷偷扩大范围、避免设计 Agent 出多余原型。

## 本任务匹配到的 skill 清单
- `problem-statement`（划清问题边界）
- `prioritization-advisor`（优先级判定）

---

## 一、不做的独立系统

| 系统 | 不做的原因 / 临时处理 |
|---|---|
| 营销系统（优惠券/秒杀/满减）| MVP 不需要；商城前端预留入口但不可点 |
| 独立支付中台 | 直接接微信支付 SDK；不抽象统一支付层 |
| 独立用户中心 | 用户表临时放 `shop_db.users`；不抽 SSO |
| 独立 ERP | 财务数据先落库不外推；不调 ERP 接口 |
| 数据 BI 平台 | 不做数据看板深度分析 |
| 消息中心 / 短信平台 | 不接入第三方短信/推送服务；验证码本地打印到日志（开发环境）|

---

## 二、商城系统不做

### 用户侧
- **微信小程序授权登录**（推迟到 M2）—— MVP 仅手机号 + 验证码
- **个人中心 / 收货地址管理 / 优惠券 / 账号设置**（M2-M3）—— 结算时地址用临时表单
- **物流跟踪页**（M3）—— 订单详情仅展示物流单号文本
- **售后申请 / 售后详情**（M3）—— 入口隐藏
- **图形验证码**（与登录限流配套，M2）—— 仅做手机号 5 次错误锁定
- **支付宝支付**（M2）—— 仅微信支付

### 商家后台
- **整个商家后台 MVP** 在本项目阶段仅做"骨架"（登录页 + 商品列表占位页）
- 后台数据看板、订单管理、售后管理、促销管理、内容管理、物流管理、权限管理、数据统计 **全部推迟**
- Vue 后台仅验证调通 PIM 后端的 `/health`

## 三、PIM 系统不做

- **数据导入导出 / Excel 模板**（M2）
- **搜索与筛选 / 批量操作 / 自定义列**（M2）
- **多渠道发布 / 字段映射 / 发布历史 / 失败重试**（M3）
- **审核工作流 / 完整度评分 / 缺失数据提醒**（M4）
- **权限管理 / 操作日志 / SSO**（M5）
- **视频上传**（SPU-05，M2）
- **属性值字典管理**（ATR-06，M2）
- **类目下商品计数**（CAT-06，M2）

---

## 四、OMS 系统不做

- **路由决策引擎 / 仓库打分 / 物流打分 / 切仓**（M2）—— MVP 假设单仓单物流
- **拆单管理 / 母子单关联**（M3）
- **售后全链路（退货退款/仅退款/换货）**（M4）
- **风控拦截 / 大额订单审核 / 黑名单地址**（M2）
- **规则配置后台 / 大促规则切换**（M3）
- **消息通知 / 短信 / Push / 平台回传**（M4）
- **支付/ERP 对接**（M4）—— MVP 仅本地 mock 微信支付回调
- **多渠道接单（天猫/京东/抖音/拼多多/线下/电话/B2B）**（M4）—— MVP 仅接收商城下单
- **大促库存缓冲**（M2，保留配置默认 0）
- **库存预留态**（M2，仅做实物/锁定/可用三态，预留固定 0）

---

## 五、WMS 系统不做

- **波次拣货 / 播种式**（二期）—— MVP 仅摘果式
- **盘点（全盘/区域/抽盘/异动盘）**（二期）
- **退货管理与质检分流**（二期）
- **批次管理 / 保质期管理**（二期）—— MVP `batch_no` 固定 `INIT-YYYYMMDD`
- **ABC 分类自动计算**（二期）—— 字段保留，全 B 类
- **8 类核心报表 + 预警**（二期）
- **库存预警 / 多仓调拨 / 补货建议**（三期）
- **PDA 离线模式**（二期）—— MVP 假设网络在线
- **黄金库位推荐策略**（二期）—— MVP 推荐分值固定（已有同 SKU 库位最高分）
- **库位承重/体积超限的精细计算**（二期）—— MVP 仅校验是否超限，不算最大可放数量

## 六、技术层面不做

- **多机房双活 / 容灾**
- **链路追踪 trace 系统**（仅打日志，不接 OpenTelemetry/Jaeger）
- **APM / 全链路监控**（仅本地日志文件）
- **CDN / 静态资源加速**（图片本地存储）
- **微服务拆分**（4 个 PHP 工程已是独立部署边界，不再拆）
- **Kubernetes**（仅 docker-compose）
- **CI/CD 流水线**（开发 Agent 本地构建测试，不部署到云）
- **数据库读写分离 / 分库分表**
- **完整的事件版本号**（M2，MVP 仅做 Idempotency-Key）
- **多语言 / 国际化**（接口预留 locale，不实现）

---

## 七、何时把 non-goals 移到 MVP

下列情形允许重新拍板把某项加回 MVP（必须用户书面确认）：
1. PRD 中某 M1 功能与本表冲突 → 以 PRD 为准（写入返工记录）
2. 用户主动追加（如"我要做售后"）→ 主控写入 progress.md【当前问题】区，重做 task-spec
3. 跨系统联调发现强依赖（如 WMS 不分批次无法测出库）→ 升级用户决策

**禁止：开发 Agent 自行扩大范围 → 直接返工。**

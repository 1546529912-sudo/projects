# 模块一：客户管理 P0 功能清单

> 产出日期：2026-05-05
> 范围：模块一客户管理 P0（必须先做）功能，含前置登录与权限体系

---

## 说明

以下功能条目按"用户登录/认证优先，其余按业务流程顺序排列"原则组织。
登录与权限为所有 P0 功能的前置条件，故排在最前。

## F-00：用户登录 / 登出

```
功能名称：用户登录 / 登出
用户：销售员、销售主管、管理员（系统所有角色）
解决问题：用户无法在无身份认证的情况下访问系统，需要一个安全且简洁的入口进入 CRM，同时能够安全退出。
功能描述：
  1. 登录页面提供账号+密码登录方式，输入合法凭据后进入系统首页。
  2. 登录失败时给出明确提示（账号不存在 / 密码错误），连续失败 5 次后锁定账号并提示联系管理员。
  3. 登出操作清除当前会话，跳转回登录页，不留残余权限。
优先级：最高
验收标准：
  1. 正确账号密码登录成功，跳转至系统首页。
  2. 错误密码提示"账号或密码不正确"，不暴露是哪个字段出错。
  3. 连续失败 5 次后，账号被锁定，提示"账号已锁定，请联系管理员"。
  4. 登出后访问任意内页自动重定向至登录页，无法绕过。
  5. 不同角色登录后看到的导航菜单与首页数据符合其角色权限（与 F-01 联动验收）。
第一版不做：
  - 短信验证码登录
  - 第三方 OAuth 登录（企业微信、钉钉、飞书 SSO）
  - 记住登录状态超过 8 小时（默认会话超时 8 小时）
  - 自助找回密码（第一版由管理员重置）
关联进度项：（progress.md 中暂无此条目，需新增）
```

## F-01：基础角色权限（销售员 / 销售主管 / 管理员）

```
功能名称：基础角色权限（销售员 / 销售主管 / 管理员三种角色的数据范围和功能权限）
用户：系统所有角色；管理员负责配置和维护
解决问题：
  不同角色的职责不同，若无权限控制，销售员会看到他人客户、主管会误操作管理员才能做的事，导致数据泄漏和越权操作。
功能描述：
  1. 系统内置三种基础角色：销售员、销售主管、管理员。
  2. 数据权限：
     - 销售员：只能看到自己负责的客户、线索、跟进记录、商机。
     - 销售主管：能看到本部门所有成员的数据。
     - 管理员：能看到全公司所有数据。
  3. 功能权限（以客户管理模块为基准）：
     - 新建客户：销售员 ✅ / 主管 ✅ / 管理员 ✅
     - 编辑自己负责的客户：销售员 ✅ / 主管 ✅ / 管理员 ✅
     - 删除客户：销售员 ❌ / 主管 ❌ / 管理员 ✅
     - 归档客户：销售员 ✅ / 主管 ✅ / 管理员 ✅
     - 转移客户：销售员 ❌ / 主管 ✅ / 管理员 ✅
     - 修改来源记录：销售员 ❌ / 主管 ✅ / 管理员 ✅
     - 审批状态回退：销售员 ❌ / 主管 ✅ / 管理员 ✅
     - 标记退款处理决定：销售员 ❌ / 主管 ✅ / 管理员 ✅
     - 修改系统设置：销售员 ❌ / 主管 ❌ / 管理员 ✅
  4. 管理员可在系统设置中为用户指定角色；角色变更立即生效。
优先级：最高
验收标准：
  1. 销售员登录后，客户列表只显示自己负责的客户，不出现他人客户。
  2. 销售员不显示"转移客户"按钮，不显示"删除客户"选项。
  3. 销售主管登录后，客户列表显示本部门所有成员的客户，可正常执行转移操作。
  4. 管理员登录后，看到全公司所有客户，可执行删除、系统设置修改操作。
  5. 将用户角色从销售员改为销售主管后，该用户下次访问即生效新权限。
  6. 销售员访问不属于自己的客户详情 URL，系统返回"无权限"页面，不展示数据。
第一版不做：
  - 四级角色体系（总监层级）留 P1 阶段随模块五同步做
  - 字段级权限控制（Tab 级控制已满足 P0 需求）
  - 自定义角色创建
  - 权限变更审计日志（P1 跟进）
关联进度项：（progress.md 中暂无"用户登录"条目；"基础权限（销售员 / 主管 / 管理员数据范围与操作权限）"对应 progress.md 模块一 P0 第 14 条）
```

## F-02：线索录入

```
功能名称：线索录入
用户：销售员、销售主管
解决问题：
  销售员从展会、电话开发等渠道获得潜在客户信息后，没有统一的录入入口，信息散落在 Excel 或个人手机里，无法追踪和分配。
功能描述：
  1. 提供独立的"新建线索"入口，销售员手动填写姓名、手机号、邮箱、公司名称、职位、线索来源（两层下拉）、负责销售（默认当前登录人）。
  2. 手机号输入框光标离开时立即触发实时查重（见 F-04）。
  3. 提交成功后线索进入"未跟进"状态，出现在线索列表。
  4. 来源字段使用两层下拉（大类/小类），选项由管理员在系统设置中维护。
优先级：最高
验收标准：
  1. 销售员可成功新建一条包含姓名+手机号+来源的线索，提交后出现在线索列表。
  2. 手机号离开输入框后，若已存在相同号码，立即显示查重提示（见 F-04 验收标准）。
  3. 来源大类下拉包含：线上广告、线下活动、客户推荐、自主开发、其他；选择大类后展示对应小类。
  4. 负责销售默认填入当前登录用户，可手动修改。
  5. 必填字段（姓名、手机号）为空时点提交，给出字段级错误提示，不允许提交。
第一版不做：
  - Excel 批量导入线索（P2）
  - 广告平台自动同步线索（P2）
  - 官网表单自动进入 CRM（P2/系统设置集成模块）
关联进度项：模块一 P0 — 线索录入
```

## F-03：新建客户（独立入口，区别于线索转化）

```
功能名称：新建客户（独立入口）
用户：销售员、销售主管、管理员
解决问题：
  部分客户不经过线索阶段直接成为客户（如老客户介绍的公司直接洽谈），需要独立的客户新建入口，不必先建线索再转化。
功能描述：
  1. 提供独立的"新建客户"入口（与"新建线索"互相独立），填写公司名称、行业、规模、地区、官网等公司信息，以及客户级别、负责销售、客户状态（默认"跟进中"）。
  2. 同步支持在新建客户时添加至少一个联系人（姓名、手机、职位）。
  3. 手机号输入框光标离开时实时查重（见 F-04）。
  4. 提交成功后客户出现在客户列表。
优先级：最高
验收标准：
  1. 销售员可在不经线索转化的情况下，直接新建一条客户记录，保存后出现在客户列表。
  2. 新建时必填字段（公司名称）为空，点击提交给出错误提示，不允许提交。
  3. 客户状态默认"跟进中"，可在表单中手动修改。
  4. 保存后客户详情页可正常查看所有填写信息。
第一版不做：
  - 从客户页批量新建（P2）
  - 名片识别自动填入（P2/AI 辅助录入）
关联进度项：模块一 P0 — 新建客户（独立入口，区别于线索转化）
```

## F-04：手机号实时查重

```
功能名称：手机号实时查重（光标离开立即触发）
用户：销售员、销售主管（任何新建/编辑线索或客户的操作者）
解决问题：
  多个销售员可能重复录入同一个客户，导致数据重复、销售抢单、跟进记录分散，严重影响数据质量和团队氛围。
功能描述：
  1. 新建线索或新建客户时，手机号输入框光标离开后，系统立即向后端发起查重请求。
  2. 查重结果分两种：
     - 重复记录属于当前登录用户：提示"⚠️ 该手机号已存在于你的线索中"，展示线索名称、创建时间、来源，提供[查看该线索]和[继续新建]两个操作。
     - 重复记录属于他人：提示"⚠️ 该手机号已由 XXX 录入，如有疑问请联系管理员处理"，提供[我知道了]操作，不暴露他人数据详情。
  3. 提示显示后，用户仍可选择继续提交；提交后系统自动打上"疑似重复"标签，进入待处理队列（供管理员后台统一处理）。
优先级：最高
验收标准：
  1. 新建线索页面输入已存在的手机号，光标离开后 2 秒内出现查重提示。
  2. 重复记录为本人线索时，提示内容包含线索名称和创建时间，并提供"查看该线索"跳转链接。
  3. 重复记录为他人线索时，提示不展示他人姓名、手机、公司等私密字段，只提示"该号码已被其他销售录入"。
  4. 用户选择继续新建并提交后，新建的记录带有"疑似重复"标签。
  5. 手机号为空时不触发查重。
第一版不做：
  - 邮箱实时查重（仅手机号实时查重；邮箱查重在 F-05 的"客户查重规则补全"里做）
  - 查重提示弹窗的复杂交互动画
关联进度项：模块一 P0 — 手机号实时查重（光标离开立即触发）
```

## F-05：客户查重规则补全（手机号 + 邮箱 + 公司名称与联系人姓名组合）

```
功能名称：客户查重规则补全
用户：系统自动执行（在录入/编辑时后台运行），结果提示给销售员和管理员
解决问题：
  手机号并非总是唯一标识（同一公司多个联系人可能共用号码、部分线索未填手机号），需要补充邮箱、公司名+联系人姓名组合作为辅助查重条件，提升查重覆盖率。
功能描述：
  1. 查重字段优先级：
     - 第一优先：手机号（完全匹配）
     - 第二优先：公司名称 + 联系人姓名组合匹配
     - 第三优先：邮箱（完全匹配）
  2. 三种条件任意一种命中，均触发"疑似重复"标签和提示。
  3. 查重范围：全库查重（不局限于当前用户的数据），但结果展示遵守数据权限（不暴露他人详情）。
  4. 查重结果统一进入疑似重复队列，供管理员后台处理（见 P1 功能）。
优先级：最高
验收标准：
  1. 新建线索时填入与已有记录相同的邮箱，提交后该线索被打上"疑似重复"标签。
  2. 新建客户时填入与已有客户相同的公司名称+联系人姓名组合，系统给出提示。
  3. 手机号已触发查重的记录，不会因邮箱或公司名也相同而重复提示（避免多重弹窗干扰）。
  4. 已归档的客户仍然参与查重，不因归档而跳过。
第一版不做：
  - 模糊匹配（如公司名相似但不完全一致的情况）
  - AI 语义查重
关联进度项：模块一 P0 — 客户查重规则补全（手机号 + 邮箱 + 公司名称与联系人姓名组合）
```

## F-06：疑似重复提交策略（允许提交，但标记疑似重复并进入待处理）

```
功能名称：疑似重复提交策略
用户：销售员（提交方）；管理员（处理方）
解决问题：
  若直接阻止重复提交，销售员在确实不同人但系统误判的情况下无法录入，影响正常业务；若完全不管控，重复数据泛滥。需要一个"允许提交但打标记、交给管理员裁决"的中间策略。
功能描述：
  1. 查重命中时，给出软提示（警告而非阻止），用户可点击"继续新建"强行提交。
  2. 强行提交后，该条记录自动打上"疑似重复"标签。
  3. 打上标签的记录进入管理员后台的"疑似重复"待处理列表。
  4. 在日常列表中，"疑似重复"标签以醒目颜色标注，提示销售员和主管关注。
优先级：最高
验收标准：
  1. 查重提示出现后，点击"继续新建"仍可成功提交，不被系统阻止。
  2. 强行提交的记录在列表页显示"疑似重复"标签（颜色醒目，如橙色）。
  3. 该记录出现在管理员后台"疑似重复待处理"列表中。
  4. 未触发查重的正常录入记录，不会被打上此标签。
第一版不做：
  - 管理员后台对疑似重复的合并/删除/忽略操作（该操作属于 P1 功能）
关联进度项：模块一 P0 — 疑似重复提交策略（允许提交，但标记疑似重复并进入待处理）
```

## F-07：查重结果展示（自己的线索 / 他人的线索 两种提示）

```
功能名称：查重结果展示（区分自己的线索与他人的线索）
用户：销售员（查看提示）
解决问题：
  查重结果涉及数据隐私，展示他人完整数据会违反数据权限原则；同时若提示内容太少，销售员无法判断是否真的重复，需要在"够用"和"不越权"之间取得平衡。
功能描述：
  1. 自己的线索（重复记录归属为当前登录用户）：
     - 提示文案：⚠️ 该手机号已存在于你的线索中
     - 显示内容：线索名称、创建时间、来源
     - 操作按钮：[查看该线索]（跳转详情页）、[继续新建]
  2. 他人的线索（重复记录归属为其他销售员）：
     - 提示文案：⚠️ 该手机号已由其他销售录入，如有疑问请联系管理员处理
     - 不展示对方姓名、手机、公司等私密字段
     - 操作按钮：[我知道了]
优先级：最高
验收标准：
  1. 手机号与自己的线索重复时，提示中出现该线索的名称和来源，并可点击跳转。
  2. 手机号与他人的线索重复时，提示不出现对方的姓名、手机号、公司等任何私密信息。
  3. 两种提示文案与设计规范一致，不出现混用的情况。
  4. 查重结果提示在光标离开后 2 秒内渲染完成。
第一版不做：
  - 在提示中展示对方销售员的姓名（隐私保护，只显示"其他销售"）
  - 历史重复记录在列表中的批量追溯展示
关联进度项：模块一 P0 — 查重结果展示（自己的线索 / 他人的线索 两种提示）
```

## F-08：线索转化客户（同时生成客户 + 联系人，可选创建商机）

```
功能名称：线索转化客户
用户：销售员、销售主管
解决问题：
  线索跟进到一定程度后，需要正式"升级"为客户，并同时建立联系人和商机，若需要手动重复填写已有的线索信息，会降低效率并引入错误。
功能描述：
  1. 在线索详情页提供"转化"按钮，点击后弹出转化确认页。
  2. 转化页分三个区域：
     - 将创建的客户（公司相关字段自动从线索带入，支持修改）
     - 将创建的联系人（个人相关字段自动从线索带入，支持修改）
     - 是否同时创建商机（勾选框，可选）
  3. 线索字段自动填入逻辑：
     - 公司名称、行业（若对接工商数据则自动拉取）直接带入客户表
     - 姓名、手机、邮箱、职位直接带入联系人表
     - 负责销售继承自线索的负责销售
     - 客户状态默认"跟进中"
  4. 转化后：原线索标记为"已转化"，保留不删除；线索详情页记录转化结果；客户详情页记录来源线索。
  5. 勾选"创建商机"时，商机名称自动生成为"公司名称-项目"，预计金额需手填。
优先级：最高
验收标准：
  1. 点击转化后，弹出转化确认页，线索中已有的字段自动填入对应客户/联系人字段。
  2. 确认转化后，系统同时生成一条客户记录和一条联系人记录，均可在对应列表中查到。
  3. 原线索状态变为"已转化"，线索详情页出现"已转化为客户：XXX"的记录。
  4. 客户详情页的来源字段中可追溯到对应线索。
  5. 勾选"创建商机"后确认，商机列表中出现对应商机记录，关联客户正确。
  6. 未勾选"创建商机"时，不生成商机记录。
第一版不做：
  - 转化时自动拉取第三方工商数据（企查查/天眼查对接，该条目独立为 F-09）
  - 转化后自动发送通知给财务或其他角色
关联进度项：模块一 P0 — 线索转化客户（同时生成客户 + 联系人，可选创建商机）
```

## F-14：客户状态流转（跟进中→意向客户→谈判中→已成交，三种触发方式）

```
功能名称：客户状态流转
用户：销售员（手动触发）、系统自动触发（关联动作）
解决问题：
  客户在销售过程中会经历不同阶段，若状态不能及时流转，主管无法判断各客户进度，报表数据失真，关联的商机/订单状态也无法联动。
功能描述：
  1. 客户状态流转路径：跟进中 → 意向客户 → 谈判中 → 已成交；任意状态可流向"已流失"。
  2. 三种触发方式：
     - 销售员手动改：在客户详情页点选状态（内联编辑）
     - 关联动作自动触发：商机标记赢单且合同确认后，客户状态自动更新为"已成交"
     - 跟进时顺带更新：填写跟进记录时，可同步修改客户状态
  3. 允许跳级（如直接从"跟进中"变为"已成交"）。
  4. 非"已成交"状态回退：填写回退原因后直接回退，仅做记录，无需审批。
  5. "已成交"状态回退：需发起审批流程（见 P1 功能，F 条目不在 P0 范围）；P0 阶段只做到允许销售员申请回退，审批逻辑在 P1 补充。
优先级：最高
验收标准：
  1. 销售员在详情页手动将状态从"跟进中"改为"意向客户"，保存后状态标签即时更新。
  2. 状态可跳级：直接从"跟进中"变为"已成交"，系统不报错。
  3. 跟进记录中填写"更新状态为谈判中"，保存后客户状态同步变更。
  4. 将已成交客户回退时，系统提示"已成交状态回退需要主管审批"，进入待审批队列（P0 阶段不阻止提交，但标记需审批）。
  5. 非已成交状态回退时，系统要求填写原因，填写后直接完成，无需审批。
第一版不做：
  - 已成交回退审批的审批流完整实现（P1 功能）
  - 退款触发的状态自动变更（P1 功能，需外部系统集成）
关联进度项：
  - 模块一 P0 — 客户状态流转（跟进中→意向客户→谈判中→已成交，三种触发方式）
```

## F-15：客户状态流转规则（含已流失，允许跳级，限制回退）

```
功能名称：客户状态流转规则
用户：系统规则层（对所有用户生效）
解决问题：
  若状态可以随意改、任意回退，销售员可能为了美化数据频繁修改状态，导致数据失真和业绩计算混乱。需要明确的规则约束哪些状态变更是自由的，哪些需要审批。
功能描述：
  1. 合法状态集合：跟进中、意向客户、谈判中、已成交、已流失。
  2. 允许跳级正向流转（如跟进中→已成交）。
  3. 允许任意状态流向"已流失"（直接操作，填写流失原因）。
  4. 非"已成交"状态回退（如意向客户→跟进中）：允许，填写原因即可，系统记录。
  5. "已成交"状态回退：P0 阶段记录申请+原因，标记为"待主管审批"；正式审批流在 P1 实现。
  6. 所有状态变更均在客户操作日志中留痕（变更前状态、变更后状态、操作人、操作时间、原因）。
优先级：最高
验收标准：
  1. 客户详情页状态下拉选项中，包含全部 5 种状态（跟进中/意向客户/谈判中/已成交/已流失）。
  2. 将"意向客户"回退到"跟进中"，系统要求填写原因，填写后直接保存，不弹出审批提示。
  3. 将"已成交"回退，系统提示"需要主管审批"，创建待审批记录，不立即执行状态变更。
  4. 客户操作日志中，每次状态变更均记录"由 A 变为 B，操作人：XXX，时间：XXX，原因：XXX"。
  5. 标记"已流失"时，系统要求填写流失原因（下拉选项 + 补充说明），不允许不填原因直接流失。
第一版不做：
  - 完整的已成交回退审批流（P1）
  - 退款触发的状态变更（P1，需外部系统对接）
  - 全自动状态判断（暂不做）
关联进度项：模块一 P0 — 客户状态流转规则（含已流失，允许跳级，限制回退）
```

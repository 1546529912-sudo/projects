# Design Framework Proposal
## 模块一：客户管理 P0 功能 — 设计框架方案

> 产出日期：2026-05-05
> 阶段：Design Framework Gate 第一轮（待用户确认）
> 设计Agent负责人：CRM UI/UX 设计

---

## 设计背景理解

本次设计对象是面向专业销售团队的 CRM 系统，核心用户是：

- **销售员**：每天高频操作，需要快速录入线索、查找客户、记录跟进
- **销售主管**：需要监管团队客户进展、审批状态变更、掌握整体数据
- **管理员**：需要管理权限、处理重复数据、查看全局信息

**关键设计约束**：

1. 工具型产品，不是展示型产品——效率优先，不做视觉炫技
2. 高频使用，长时间盯屏——护眼、低噪声、信息层级清晰
3. 同屏信息量大（客户列表 + 筛选 + 状态标签 + 操作列）——需要克制的视觉语言
4. 涉及多种状态颜色（A/B/C级别、客户状态、查重标签）——色彩必须有系统性

---

## 明确不采用的风格（反例）

在进入三个方向之前，先明确排除以下设计风格：

**X 廉价渐变风**
蓝紫渐变按钮、彩虹色标签、渐变背景卡片。这类风格在阿里云早期、部分国内 SaaS 后台中常见，显廉价，且让颜色失去语义性。

**X 重型仪表盘风**
深色背景 + 数据大屏风格，炫酷但不适合日常高频的客户管理操作场景。重色调增加眼疲劳，且与客户录入、列表浏览等操作场景不匹配。

**X 普通后台模板风**
蓝色顶栏 + 白色内容区 + 每个按钮都有圆角阴影的"Ant Design 默认主题"风格。没有差异化，视觉无层级，会让产品看起来"像是随便套了个模板"。

**X 过度留白的极简风**
每个页面都大量留白，信息密度低，看起来像官网而不是工具。CRM 的本质是效率工具，过少的信息密度会让销售员需要频繁翻页、滚动，降低使用效率。

## 三个可选设计方向

---

### 方向 A：「工具理性」——克制、专业、无装饰

**一句话定位**：为长期使用设计的专业销售工具，视觉服务于数据，不服务于美感。

**视觉关键词**：克制、理性、高效、数据驱动、无噪声

**色彩方案**

| 色彩角色 | 色值 | 使用场景 |
|---|---|---|
| 主色 | `#2563EB` | 主要按钮、激活导航、链接 |
| 主色 Hover | `#1D4ED8` | 按钮 hover 状态 |
| 主色浅底 | `#DBEAFE` | 选中行、标签底色 |
| 页面背景 | `#F9FAFB` | 全局背景 |
| 卡片背景 | `#FFFFFF` | 内容区、列表 |
| 侧边栏背景 | `#111827` | 深色侧边导航 |
| 主文字 | `#111827` | 标题、关键数据 |
| 正文 | `#374151` | 表格内容、表单 |
| 次要文字 | `#6B7280` | 辅助说明、时间戳 |
| 边框/分割线 | `#E5E7EB` | 表格行分割、卡片边框 |
| A级客户标签 | `#DC2626` / `#FEE2E2` | 高优先级标记 |
| B级客户标签 | `#D97706` / `#FEF3C7` | 中优先级标记 |
| C级客户标签 | `#6B7280` / `#F3F4F6` | 低优先级标记 |

**字体风格**：system-ui / PingFang SC，不引入自定义字体。字重有且只有 400（正文）/ 500（标签、表头）/ 600（标题）三档，不混用更多字重。

**间距密度**：中密度偏高。表格行高 40-48px，列表不留过多空白，侧重信息密度。

**圆角**：按钮 6px，卡片/弹窗 8px，标签 4px。不用更大圆角（避免"圆润感"冲淡专业气质）。

**阴影**：极度克制。只在弹窗和下拉菜单上使用浅阴影（`box-shadow: 0 4px 16px rgba(0,0,0,0.08)`），列表、卡片无阴影，用边框替代。

**信息密度倾向**：高密度工具型

**适合用户群体和场景**：
- 习惯使用 Linear、Jira、Salesforce 等工具的技术型销售或 B2B 销售员
- 主管和管理员——需要同屏看到尽量多的数据
- 追求效率、不需要"被界面引导"的熟练用户

### 方向 B：「清醒简练」——更多留白、轻量感、视觉层级通过尺寸和字重区分

**一句话定位**：比传统 CRM 更现代、更轻量，既保持效率又减少视觉压迫感。

**视觉关键词**：现代、轻量、清晰、呼吸感、层次感

**色彩方案**

| 色彩角色 | 色值 | 使用场景 |
|---|---|---|
| 主色 | `#0F172A` | 侧边栏背景、主标题（用深色代替蓝色作为主色调） |
| 强调色 | `#3B82F6` | 主要按钮、链接、激活状态 |
| 强调色浅底 | `#EFF6FF` | 选中状态、hover 提示 |
| 页面背景 | `#FAFAFA` | 整页背景 |
| 卡片背景 | `#FFFFFF` | 列表区、内容卡片 |
| 主文字 | `#0F172A` | 公司名、重要数据 |
| 正文 | `#475569` | 表格内容 |
| 次要文字 | `#94A3B8` | 时间、辅助说明 |
| 边框 | `#F1F5F9` | 极浅边框，只有在 hover 时才明显 |
| A级客户 | `#EF4444` / `#FEF2F2` | — |
| B级客户 | `#F59E0B` / `#FFFBEB` | — |
| C级客户 | `#64748B` / `#F8FAFC` | — |

**字体风格**：system-ui，标题与正文字号差距更大（H2 用 20px，正文用 13px），通过字号差距建立层级，减少颜色层级。

**间距密度**：中密度平衡型。表格行高 52px，每行有更多呼吸感。筛选区与列表之间有明显分隔间距。

**圆角**：按钮 8px，卡片 12px，标签 6px。偏圆润，视觉上更"现代"。

**阴影**：比方向 A 稍多一层。列表卡片有 `0 1px 3px rgba(0,0,0,0.06)` 的浅卡片阴影，与背景拉开一点层次感。弹窗阴影稍深。

**信息密度倾向**：中密度平衡型

**适合用户群体和场景**：
- 对视觉有一定要求、不希望界面太"老派"的销售团队
- 中小规模销售团队（5-50人），客户数量不是特别庞大，不需要极限榨取信息密度
- 刚从 Excel 迁移过来、需要一点"亲切感"来降低学习成本的用户

### 方向 C：「精密仪器」——高信息密度，数据优先，接近 Linear/Stripe 的专业感

**一句话定位**：把销售工具做到接近开发者工具的信息密度和操作效率，让熟练用户感受到尊重。

**视觉关键词**：精密、专业、高效、数据清晰、无冗余

**色彩方案**

| 色彩角色 | 色值 | 使用场景 |
|---|---|---|
| 主色 | `#1E293B` | 侧边栏、顶部导航（几乎接近黑的深蓝灰） |
| 强调色 | `#2563EB` | 主操作按钮、激活状态、链接 |
| 选中底色 | `#EFF6FF` | 选中行 |
| 页面背景 | `#F8FAFC` | 全局背景（非纯白，有极淡的蓝灰色调） |
| 卡片/列表背景 | `#FFFFFF` | 主要内容区 |
| 主文字 | `#1E293B` | 公司名、关键字段 |
| 正文 | `#334155` | 表格正文 |
| 次要文字 | `#64748B` | 时间、负责人、辅助标签 |
| 边框 | `#E2E8F0` | 表格水平分割线 |
| A级客户 | `#DC2626` | 只用文字色，无色块背景 |
| B级客户 | `#D97706` | 只用文字色，无色块背景 |
| C级客户 | `#94A3B8` | 灰色，代表低优先级 |

**字体风格**：system-ui。字号整体偏小（正文 13px），行高克制（1.5），用更密的字号换取更多信息可见度。标题和内容的字重差距是主要层级手段。

**间距密度**：高密度工具型。表格行高 36-40px（比方向 A 还紧），追求在不滚动的情况下能看到更多条目。

**圆角**：按钮 4px，卡片 4px，标签 3px。接近直角，专业工具感强，避免"可爱感"。

**阴影**：完全不用阴影。用边框和背景色差异区分层次。这是最接近 Linear 的选择。

**信息密度倾向**：高密度工具型（最高密度）

**适合用户群体和场景**：
- 每天处理大量客户的专业销售员（客户数量 100+ 的重度用户）
- 对工具有较高审美要求的团队（类似用过 Linear、Figma 等工具的人）
- 以管理员和销售主管为主要目标用户的团队（他们需要在一个屏幕上掌握最多数据）

## 推荐方向及理由

**推荐：方向 C「精密仪器」，备选方向 A「工具理性」**

**推荐方向 C 的核心理由：**

1. **与标杆产品最接近**：Linear 和 Stripe Dashboard 都是高密度、无阴影、以字重和颜色强度区分层级的风格，方向 C 最直接对标这两个产品。

2. **符合真实用户场景**：销售员每天要在客户列表里快速扫视 20-50 条记录，越高的信息密度意味着越少的滚动、越快的扫视效率。不是展示型页面，不需要为"好看"牺牲密度。

3. **颜色语义最干净**：方向 C 用纯文字颜色而不是色块来区分 A/B/C 级别，既保留了颜色识别，又不让色块在列表里造成视觉噪音。这与颜色规范中"禁止同一模块内使用超过3种颜色"的原则一致。

4. **4px 圆角更耐看**：适合长时间工作的工具界面。8-12px 的大圆角在展示产品中很流行，但在数据密集的工具里会让界面显得"软"，方向 C 的 4px 圆角更符合"专业工具"的气质。

5. **无阴影原则更高级**：阴影是廉价层次感的来源，真正高级的工具界面（Linear、Notion）用颜色深度和边框厚度做层次区分，方向 C 完全不用阴影，是三个方向中最克制的选择。

**如果用户希望界面更"亲和"一些，建议选方向 A**，它在信息密度和视觉克制度上与方向 C 接近，但保留了一点更传统的 SaaS 感（有按钮色块、稍大圆角），不会让不熟悉 Linear 风格的用户感到陌生。

**不推荐方向 B 作为主方向**，但方向 B 的"Tab 式快速筛选"和"圆点色标"是值得借鉴的局部设计元素，可以在确认方向后融合进最终规范。

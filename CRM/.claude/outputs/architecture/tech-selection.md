# CRM 技术选型方案
## Architecture Tech Selection — 第一阶段产物

> 产出日期：2026-05-05
> 阶段：架构 Agent 第一轮（ARCH_TECH_SELECTION_READY）
> 状态：用户已确认（团队偏好 Node、阿里云、首版小规模、单租户）

---

## 一、定位与边界

- 项目类型：全能型 CRM Web 系统，单租户
- 首版规模：单团队 30 人以内，客户和商机数据量在万级到十万级之间
- 部署区域：中国大陆，阿里云
- AI 能力：转写与结构化均通过外部 API 调用，CRM 不自建模型
- 设计风格：方向 1 Linear Pro，浅色主界面、低装饰、深黑主动作色

---

## 二、前端选型

| 类别 | 选型 | 理由 |
|---|---|---|
| 框架 | React 18 + TypeScript | 团队最熟，生态强，适合复杂表格与状态 |
| 构建工具 | Vite | 启动快、热更新好 |
| 样式 | TailwindCSS + shadcn/ui | 完美适配 Linear Pro 浅色克制风格，组件源码可控 |
| 表格 | TanStack Table | 满足客户列表/商机列表/报表的复杂列、排序、筛选 |
| 数据请求 | TanStack Query | 缓存、重试、并发控制开箱即用 |
| 全局状态 | Zustand | 轻量，避免 Redux 样板 |
| 表单 | React Hook Form + Zod | 与后端 DTO 共享 schema |
| 路由 | React Router v6 | 标准方案 |
| 图表 | Recharts | 轻量，覆盖漏斗、趋势、对比够用 |
| 图标 | Lucide | 与 shadcn/ui 配套，风格统一 |

---

## 三、后端选型

| 类别 | 选型 | 理由 |
|---|---|---|
| 框架 | NestJS + TypeScript | 模块化、装饰器友好、与前端共享类型 |
| ORM | Prisma | 类型安全、迁移可控、性能足够 |
| 鉴权 | JWT + Passport | 无状态认证，便于扩展刷新 token |
| 权限模型 | RBAC + Owner 数据归属 | 销售员/主管/管理员三层 + 数据 owner_id |
| 校验 | class-validator + class-transformer | NestJS 标准用法 |
| 接口约定 | REST `/api/v1`，统一响应 `{ code, message, data, pagination }` | 前后端协议统一，便于测试 |
| 文档 | Swagger / OpenAPI | 自动生成，便于联调 |

---

## 四、数据库与缓存

| 类别 | 选型 | 理由 |
|---|---|---|
| 主数据库 | PostgreSQL 15（阿里云 RDS） | 强关系 + JSONB 适合自定义字段、状态机、跟进结构化结果 |
| 缓存 | Redis 7（阿里云云数据库 Redis 版） | 会话辅助、热点数据、防重复提交、限流 |
| 队列 | BullMQ（基于 Redis） | 跟进提醒、超期升级、AI 异步任务、工作流执行 |
| 全文/模糊搜索 | PostgreSQL `pg_trgm` 索引 | 客户/商机模糊搜索首版够用，后期可换 ES |
| 文件存储 | 阿里云 OSS | 语音原始文件、合同 PDF、附件 |

---

## 五、AI 链路（首版外接）

| 类别 | 选型 | 备注 |
|---|---|---|
| 语音转写 | 阿里云智能语音 ASR | 支持长语音、流式转写 |
| 结构化提取 | 阿里云通义千问（Qwen） | 同账号便于结算、合规 |
| 落地策略 | 原文 + 转写文本 + 结构化结果分别存储；销售人工确认后才入库结构化 | 与产品确认的"两个确认节点"一致 |
| 抽象层 | 后端封装 `AIProvider` 接口 | 后续可替换为 OpenAI 兼容或自建模型 |

## 六、通知与集成

| 类别 | 选型 | 备注 |
|---|---|---|
| 站内通知 | 自建（DB + WebSocket / 轮询） | 首版可用轮询，后期升级 |

## 八、关键架构原则（首版）

1. 单租户，但所有数据查询强制带权限范围（owner_id + 团队层级）
2. 所有写操作记录变更日志，业务操作日志与系统操作日志分两条链路
3. 所有 AI 任务进队列，不阻塞用户接口
4. 所有提醒、超期升级、状态自动流转都通过工作流引擎触发，不写在业务接口中
5. 工作流默认停用，运营确认后再启用
6. 所有外部集成（ASR / LLM / 邮件 / 短信 / OSS / 第三方工商数据 / 财务系统）封装为可替换 Provider
7. 接口契约一旦确认不允许开发 Agent 自行变更
8. 业务边界规则必须在数据模型或服务层显式落点，例如：
   - 客户状态机（含 已流失、跳级、限制回退）
   - 客户查重组合（手机号、邮箱、公司名 + 联系人）
   - 疑似重复仍允许提交但标记
   - 赢单 ≠ 已成交，已成交以回款到账为准
   - 业绩统计按回款到账，分期按每笔到账计入
   - 来源分析按线索创建时间归因，不按成交时间
   - 跟进提醒跟随客户负责人，转移后同步转移

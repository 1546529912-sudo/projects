# CRM 模块三：销售管理（完整版）

> 学习路径：✅ 模块一：客户管理 → ✅ 模块二：跟进记录 → ⏭ **模块三：销售管理（当前）** → ⬜ 模块四：数据报表 → ⬜ 模块五：系统设置

---

## 一、是什么？

前两个模块解决的是：
- 模块一：**客户是谁**（客户管理）
- 模块二：**跟进了什么**（跟进记录）

模块三要解决的是：

> **这个客户，能不能成交？成交的进度在哪里？**

销售管理的核心对象是**商机（Opportunity）**，也叫"销售机会"。

如果说客户管理是"花名册"，跟进记录是"工作日记"，那商机就是"战报"——每一笔潜在的生意，从发现到成交（或失败），全程追踪。

---

## 二、三个核心对象

```
商机（Opportunity）   ← 一笔潜在的生意
    ↓ 谈成了
报价单（Quote）       ← 给客户的价格方案
    ↓ 客户确认了
合同（Contract）      ← 正式签署的协议
```

三个对象有先后关系，但不是每个 CRM 都要全部实现，可以根据业务复杂度裁剪。

---

## 三、商机

### 商机和客户状态的关系

商机状态是细粒度的，客户状态是粗粒度的，两者是父子关系，不能合并：

```
客户状态（粗）          商机状态（细）
跟进中         ←→      初步接触/需求确认/方案报价/谈判中
已成交         ←→      赢单（有合同 + 有回款）
已流失         ←→      输单
```

**赢单 ≠ 已成交**：赢单是谈成了，已成交是钱到账了。两个概念不能混淆。

### 商机核心字段

**基本信息**

| 字段 | 说明 |
|------|------|
| 商机名称 | 如"阿里巴巴-ERP采购项目" |
| 关联客户 | 挂在哪个客户下面 |
| 负责销售 | 谁在跟这个商机 |
| 创建时间 | 什么时候发现这个机会的 |

**金额相关**

| 字段 | 说明 |
|------|------|
| 预计金额 | 这笔生意大概多少钱 |
| 实际成交金额 | 最终签了多少（赢单后填） |

**进度相关**

| 字段 | 说明 |
|------|------|
| 商机阶段 | 现在走到哪一步了 |
| 预计成交日期 | 销售新建商机时手动填写 |
| 最后更新时间 | 系统自动记录 |
| 赢/输单原因 | 结束时填，为什么赢了或输了 |

### 商机阶段流转

```
初步接触 → 需求确认 → 方案报价 → 谈判中 → 赢单/输单
```

- **大部分阶段**：销售手动推进，主管复核
- **赢单**：上传已签合同后，系统辅助判定，触发通知财务/订单系统
- **输单**：只能销售手动标记，没有客观凭据

### 赢单触发链路

```
销售上传已签合同
        ↓
系统识别合同状态为"已签署"
        ↓
商机自动推进→赢单
        ↓
触发通知财务/订单系统
        ↓
等待付款到账
        ↓
客户状态变为已成交
```

### 一个客户能有几个商机？

可以有多个商机，但**只能有一个负责销售**。

真实业务里，主管不会允许两个销售同时跟同一个客户，会造成客户被骚扰、显得公司不专业。系统层面用防撞单机制保证一个客户只有一个负责人。

```
阿里巴巴（一个客户，一个负责销售）
├── 商机A   ERP采购    负责：张三
└── 商机B   培训服务   负责：张三（同一个人）
```

### 客户状态如何展示多个商机？

客户状态从单一字段改为**多标签**，以商机状态驱动：

```
客户列表
阿里巴巴   有成交 | 跟进中   ← 同时显示两个标签
```

客户详情页展示完整情况：

```
阿里巴巴
├── 商机A  ERP采购   已成交  155万
└── 商机B  培训服务  谈判中   80万
```

### 商机入口设计

**入口一：客户详情页（最常用）**

```
客户详情页  阿里巴巴
├── 基本信息
├── 跟进记录
└── 商机
      [+ 新建商机]   ← 自动关联该客户
```

**入口二：首页快速新建**

```
首页  我的商机
[+ 新建商机]   ← 需要手动选择关联客户
```

### 商机在首页如何展示？

首页只展示**需要关注的商机**，不是全部：

```
我的商机
━━━━━━━━━━━━━━━━━━━━━━━━━━━
⚠️ 即将到期    阿里巴巴ERP    谈判中    155万    3天后到期
⚠️ 即将到期    腾讯培训       方案报价   80万    5天后到期
📌 长期未推进  字节跳动实施   需求确认  200万   30天未更新
```

首页底部放"查看全部商机"入口，点进去是完整的商机列表页，支持筛选、排序、搜索。

## 四、报价单

### 报价单是什么？

报价单是销售给客户的价格清单，告诉客户要买的东西报价是多少。

```
报价单
━━━━━━━━━━━━━━━━━━━━━━━━━━━
客户：阿里巴巴
报价单编号：QT-2026-0426
日期：2026年4月26日
有效期：30天
━━━━━━━━━━━━━━━━━━━━━━━━━━━
序号  产品/服务        数量   单价    小计
1     ERP软件授权      1套    80,000  80,000
2     实施服务         20天   3,000   60,000
3     售后维保（1年）  1年    15,000  15,000
━━━━━━━━━━━━━━━━━━━━━━━━━━━
合计：155,000元
备注：价格含税，不含差旅费
```

### 报价单在销售流程中的位置

```
初步接触
    ↓
需求确认
    ↓
方案报价   ← 销售给客户发报价单
    ↓
谈判中     ← 客户可能砍价，报价单可能改好几版
    ↓
赢单       ← 最终确认的那版报价单，变成合同金额
```

### 报价单核心字段

| 字段 | 说明 |
|------|------|
| 报价单编号 | 系统自动生成，如 QT-2026-0426 |
| 关联商机 | 属于哪个商机 |
| 客户名称 | 自动带出 |
| 有效期 | 报价有效多少天 |
| 产品明细 | 从产品目录选择，自动带出标准价 |
| 合计金额 | 自动计算 |
| 备注 | 特殊说明 |

### 报价单版本管理

一个商机可能有多个版本的报价单，系统只记录**金额和时间**，不记录原因：

```
v1   155,000   2026-01-15
v2   140,000   2026-01-22
v3   132,000   2026-01-28
```

**原因记在哪里？** 销售在跟进记录里自然就会写，不需要在报价单里重复填写：

```
1月22日  跟进记录   拜访张总，客户要求优惠5%   ← 原因在这里
1月22日  报价单     v1→v2   155,000→140,000    ← 金额变化在这里
```

两者结合，主管对照时间轴就能看清楚完整的谈判过程。

### 报价单审批流程

当销售填写的价格低于产品目录里设定的最低价时，自动触发审批：

```
销售填报价单
        ↓
价格低于最低价
        ↓
系统自动锁定报价单（不能发给客户）
        ↓
自动通知主管审批
        ↓
主管通过   →  报价单解锁，销售可导出PDF发给客户
主管拒绝   →  销售修改价格重新提交
```

**多级审批规则（示例）**

```
折扣在10%以内   →  直属主管审批
折扣超过10%     →  直属主管 + 总监 双重审批
```

**审批通知方式**

```
站内消息提醒
手机推送通知
企业微信通知   ← 主管不一定一直开着电脑
```

### 报价单发给客户的方式

报价单以**PDF格式**导出，销售通过微信/邮件发给客户。客户不需要登录CRM。

```
销售填完报价单
        ↓
点"导出PDF"
        ↓
系统自动生成格式规范的报价单
        ↓
销售下载，发给客户
```

**PDF模板可配置（在系统设置里）**

```
系统设置
└── 报价单模板
      ├── 上传公司Logo
      ├── 公司名称和地址
      └── 备注默认内容
```

## 五、合同

### 首版轻量做法

第一版不需要做完整合同系统，只需要在商机下支持**合同附件上传 + 签署状态记录**。

这样做的目的不是管理合同全生命周期，而是给"赢单"提供客观凭据：

```
商机详情页
└── 合同凭据
      ├── 上传已签合同PDF
      ├── 合同金额
      ├── 签署日期
      └── 签署状态：待签署/已签署
```

当合同状态变为"已签署"后，系统可以辅助判断商机进入赢单；后续是否做合同审批、合同模板、归档、作废、续签等能力，再进入完整合同管理。

### 合同管理的两种模式

| 情况 | 处理方式 |
|------|---------|
| 公司已有合同系统 | CRM对接接口，不重复建设 |
| 公司没有合同系统 | CRM内置轻量合同管理 |

系统设置里可配置：

```
系统设置
└── 合同管理模式
      ├── 内置模式（使用CRM自带合同管理）
      └── 对接模式（填写外部系统接口地址）
```

### CRM内置合同的核心字段

| 字段 | 说明 |
|------|------|
| 合同名称 | 如"阿里巴巴-ERP采购合同" |
| 关联商机 | 属于哪个商机 |
| 合同金额 | 最终签署金额 |
| 签署日期 | 双方签字盖章的日期 |
| 合同文件 | 上传PDF |
| 合同状态 | 草稿/待签署/已签署/已作废 |

## 六、产品目录

产品目录放在**系统设置**里，由管理员维护，不是销售的日常操作。

### 核心字段

| 字段 | 说明 |
|------|------|
| 产品名称 | 如"ERP软件授权" |
| 产品编码 | 唯一标识 |
| 标准售价 | 正常报价，自动带入报价单 |
| 最低售价 | 低于此价格触发审批 |
| 产品描述 | 备注说明 |

### 产品目录和报价单的关系

```
管理员在产品目录设定
├── ERP软件    标准价 80,000    最低价 65,000
└── 实施服务   标准价 3,000/天  最低价 2,500/天

销售填报价单时
└── 从产品目录选择产品，标准价自动带出
        ↓
      填写实际报价
        ↓
      低于最低价 → 触发审批
      高于最低价 → 直接提交
```

## 七、三种记录的区别

客户详情页的时间轴里，汇总展示三种记录中的前两种：

```
记录类型            谁来写          销售能看    主管能看    管理员能看
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
跟进记录            销售手动填       ✅          ✅          ✅
业务操作记录        系统自动记录     ✅          ✅          ✅
系统操作日志        系统自动记录     ❌          ❌          ✅
```

**跟进记录**：销售手动记录的沟通内容

```
1月22日  拜访张总，客户要求优惠5%
```

**业务操作记录**：系统自动记录的业务数据变更，销售和主管都能看

```
1月22日  报价单 v1→v2   155,000→140,000
1月22日  商机阶段  方案报价→谈判中
1月28日  上传合同文件
```

**系统操作日志**：只有管理员能看，不在客户详情页展示

```
1月22日  张三  登录系统  IP:192.168.1.1
1月22日  张三  删除了一条跟进记录
1月25日  张三  导出了客户列表
```

### 主管在客户详情页看到的完整时间轴

```
阿里巴巴  客户详情页
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1月28日  📝 跟进记录   电话确认，客户接受132,000
1月28日  💰 报价单     v2→v3   140,000→132,000
1月28日  📄 合同       上传合同文件
─────────────────────────────────
1月22日  📝 跟进记录   拜访张总，客户要求优惠5%
1月22日  💰 报价单     v1→v2   155,000→140,000
─────────────────────────────────
1月15日  📝 跟进记录   电话初次沟通，客户有意向
1月15日  💰 报价单     v1创建   155,000
```

销售只需要写跟进记录，报价单变更、合同操作、商机阶段变化由系统自动补进时间轴。

## 九、功能优先级

功能优先级按一个原则判断：

> **先让销售能把一笔生意从发现、推进、赢单/输单完整跑起来，再补价格管控、合同系统和智能分析。**

| 优先级 | 功能 | 判断理由 |
|--------|------|---------|
| P0 必须有 | 商机管理、关联客户与负责人、商机阶段流转、首页待关注商机、赢/输单原因、合同附件上传与签署状态 | 没有这些，销售管理模块就无法追踪一笔生意的完整过程；合同附件是赢单的关键凭据 |
| P1 重要 | 轻量报价单管理、报价单版本管理、产品目录、业务操作记录、客户详情页业务时间轴 | 让金额、报价变化和关键业务动作可追溯，支撑主管复盘和销售协同 |
| P2 有了更好 | 报价审批流程、多级审批、报价单 PDF 模板、CRM 内置合同管理 | 提升价格管控和合同管理效率，但依赖前面的商机、报价和产品目录数据 |
| P3 看情况 | 外部合同系统对接、系统操作日志、AI 分析商机赢率、AI 推荐下一步行动 | 属于平台集成、审计或智能增强，不影响销售主流程先跑起来 |

这个优先级的核心判断是：

```
P0 先跑通商机闭环：谁的客户、哪笔生意、推进到哪、最后赢还是输
P1 再补齐报价和过程留痕：金额怎么变、过程怎么复盘
P2 做管理管控：低价审批、合同管理、模板规范
P3 才进入系统集成、审计增强和 AI 辅助决策
```

## 十、产品迭代路径

```
第一版   商机管理 + 阶段流转 + 首页待关注商机 + 合同附件上传 + 赢/输单原因
第二版   轻量报价单 + 报价单版本管理 + 产品目录 + 业务操作记录时间轴
第三版   报价审批流程 + 报价单PDF模板 + CRM内置合同管理
第四版   外部合同系统对接 + 系统操作日志完善
第五版   AI分析商机赢率，给销售推荐下一步行动
```

## 十一、关键设计决策汇总

| 决策点 | 推荐做法 | 原因 |
|--------|---------|------|
| 一个客户几个负责销售 | 只能一个 | 防撞单，避免客户被骚扰 |
| 商机是否独立导航 | 不独立，内嵌客户详情页 + 首页入口 | 商机跟着客户走，逻辑清晰 |
| 客户有多个商机时状态怎么显示 | 多标签，以商机状态驱动 | 单一字段无法表达多个维度 |
| 报价单版本记什么 | 只记金额和时间，不记原因 | 原因在跟进记录里写，不重复填写 |
| 报价单价格管控 | 产品目录设定最低价，低于触发审批 | 防止销售乱报价 |
| 报价单发给客户的方式 | PDF导出，微信/邮件发送 | 客户不需要登录CRM |
| 合同管理 | 可配置，内置或对接外部系统 | 不同公司情况不同 |
| 产品目录放哪里 | 系统设置 | 基础数据，管理员配置，不是日常操作 |
| 业务操作记录谁能看 | 销售+主管都能看 | 和业务相关，需要协同 |
| 系统操作日志谁能看 | 只有管理员 | 系统行为监控，不是业务内容 |

## 十二、核心结论

| 维度 | 核心结论 |
|------|---------|
| 本质 | 追踪每一笔潜在生意从发现到成交的全过程 |
| 三个核心对象 | 商机 → 报价单 → 合同 |
| 最重要的概念区分 | 赢单（谈成了）≠ 已成交（钱到账了） |
| 报价单版本原因记在哪 | 跟进记录，不在报价单里重复填 |
| 三种记录的本质区别 | 跟进记录是工作日记，业务操作记录是业务流水，系统操作日志是监控录像 |
| 最容易踩的坑 | 把商机阶段和客户状态混为一谈 |

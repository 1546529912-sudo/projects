# CRM 模块二：跟进记录（完整版）

> 学习路径：✅ 模块一：客户管理 → ⏭ **模块二：跟进记录（当前）** → ⬜ 模块三：销售管理 → ⬜ 模块四：数据报表 → ⬜ 模块五：系统设置

---

## 一、是什么？

跟进记录是销售人员与客户每次互动的"日志系统"。

每一次打电话、发消息、拜访客户、发送方案，都应该留下一条记录。它回答的核心问题是：

> **"这个客户，我们上次做了什么、说了什么、下一步要做什么？"**

如果客户管理模块是 CRM 的"名片夹"，那跟进记录就是"工作日记"。两者结合，才构成完整的客户生命周期视图。

---

## 二、真实价值

表面上看只是"录入记录"，但它真正解决三个深层问题：

**防止客户资产流失**
销售离职时，如果没有跟进记录，新销售接手等于从零开始。跟进记录是公司对抗人员流动风险的核心手段。

**让管理层能介入**
主管不可能陪每个销售去拜访。跟进记录是主管唯一能看到一线情况的窗口，没有记录只能靠口头汇报，信息失真严重。

**数据驱动销售决策**
跟进了10次没成交 vs 跟进了2次就成交，差别在哪？没有跟进记录的积累，这个问题永远答不上来。

---

## 三、核心矛盾：为什么销售不愿意填

CRM 里有三个角色，诉求天然冲突：

```
销售        希望少填表、多成交、客户是"我的"
主管        希望看到真实进展、能管控团队
公司        希望客户资产沉淀、不依赖某个人
```

**公司推行 CRM，本质上是在用制度强制销售把私有信息变成公司资产。**

销售的顾虑：
- 客户被主管看到，认为跟进不力，直接介入或转给别人
- 详细沟通内容暴露了自己的谈判底牌
- 离职时记录留在公司，自己带不走

结果是**合规性填写**——填，但只填没有价值的内容：

> "已沟通，待回复。"
> "客户在考虑中。"
> "下周再联系。"

表单提交了，数据毫无意义。

---

## 四、传统设计的两难困境

**想要数据质量高，就必须让销售多填：**
字段越多，数据越结构化，对公司越有价值。但销售的感受是填表比跑业务还累，于是敷衍填写，数据质量反而更差。

**想要销售愿意填，就必须减少填写负担：**
字段减少、格式自由、随便写几个字就能提交。销售体验好了，但数据没有任何价值。

```
要求填得多   →   销售抵制，数据失真
要求填得少   →   销售配合，但数据没价值
```

这两个目标在传统设计里是跷跷板，只能选一边。所有传统 CRM 的解法，无非是在两端之间找平衡点，本质上无法跳出这个矛盾。

---

## 五、AI 如何打破这个矛盾

AI 的介入，把这个等式从根本上改变了。

**传统设计：**
```
数据质量  =  销售填写的内容
```

**AI 设计：**
```
数据质量  =  AI 处理后的内容
销售填写  =  一段随意的语音
```

销售只需要对着手机说一段话，完全不需要思考格式、字段、结构。说话的成本几乎是零。但 AI 能自动提取出客户反馈、价格意向、竞品信息、下次跟进时间……

**输入端的成本降到最低，输出端的质量反而更高。**

> 传统设计里，数据质量是销售用时间和精力换来的。AI 设计里，数据质量是机器从销售的自然表达里提取出来的。这是逻辑结构的改变，不只是功能优化。

## 六、AI 跟进记录的完整技术链路

### 整体流程

```
销售拜访完客户
      ↓
打开手机 CRM，点"新建跟进"
      ↓
上传语音 / 直接录音
      ↓
第一步：语音转文字（ASR）
      ↓
第二步：文字结构化（LLM + Prompt）
      ↓
第三步：提取标题摘要（LLM）
      ↓
销售确认 / 微调
      ↓
提交，存入数据库
```

### 第一步：语音转文字（ASR）

不需要自己开发，直接调用现成服务：

```
国内   阿里云语音识别、腾讯云、科大讯飞
国外   OpenAI Whisper、Google Speech
```

输出是一段原始文字，没有任何格式，就是把说的话转成文字。

### 第二步：结构化输出

通过 Prompt 告诉 AI 按指定格式提取信息：

```
你是一个 CRM 跟进记录助手。
我会给你一段销售人员的拜访描述，
请按以下格式提取信息并输出：

客户反馈：（客户说了什么，态度如何）
价格意向：（有没有提到价格，具体数字）
竞品信息：（有没有提到竞争对手）
待办事项：（销售需要做什么）
下次跟进：（时间和事项）

如果某项没有提到，填"无"。
```

这不是一个独立安装的模块，而是通过 Prompt 工程实现的。**Prompt 模板要支持管理员按行业自定义**，不同行业关注的字段不同。

### 第三步：提取标题

在结构化 Prompt 里同时要求输出标题：

```
额外输出：
标题：用一句话概括本次跟进的核心内容，不超过20个字。
```

### 实际效果示例

销售说的原始语音转文字后：

> "今天去见了张总，他说价格还是有点高，希望能优惠个5%，付款方式他们公司规定要分三期，我跟他说我回去跟领导申请一下，他说下周一会给我发正式的采购申请，我需要准备一个详细的实施方案给他们IT部门看"

AI 处理后自动生成：

```
标题：拜访张总，价格待确认，下周等采购申请

客户反馈：整体认可方案，价格偏高
价格意向：希望优惠5%，分三期付款
竞品信息：无
待办事项：向领导申请价格优惠；准备实施方案发给IT部门
下次跟进：下周一，等待客户发采购申请
```

### 智能体架构

整个链路封装成一个智能体：

```
智能体的能力构成
├── 工具一   调用 ASR 服务，语音转文字
├── 工具二   调用 LLM，文字结构化（内置 Prompt 模板）
└── 工具三   把结构化结果写入 CRM 数据库
```

### 关键设计细节

**两个确认节点**
语音转文字后，销售确认转写是否准确。结构化完成后，销售确认 AI 提取的内容是否正确。防止 AI 出错直接存了错误数据。

**原始语音永久保留**
不管 AI 处理得多好，原始语音是最原始的证据，要单独存档，不能因为已经转写就删掉。万一有争议，原始录音是最准确的依据。

**Prompt 模板可配置**
做软件的销售关注"竞品、决策人、采购流程"；做快消的销售关注"铺货情况、陈列位置、促销意向"。支持管理员根据行业自定义字段模板。

## 七、跟进时间轴的展示设计

### 收起状态（列表展示）

```
1月22日  🤝 拜访    拜访张总，价格待确认，下周等采购申请    [展开]
1月20日  📅 计划跟进  ⚠️ 未执行
1月15日  📞 电话    确认需求，计划安排见面
```

时间轴收起状态只显示 AI 生成的摘要标题，保持整洁。

### 展开状态（完整内容）

```
1月22日  🤝 拜访
  客户反馈：整体认可方案，价格偏高
  价格意向：希望优惠5%，分三期付款
  竞品信息：无
  待办事项：向领导申请价格优惠；准备实施方案
  下次跟进：下周一，等待客户发采购申请
  📎 附件：实施方案_v2.pdf   报价单_张总.xlsx
  🎙️ 原始语音：[播放]
```

## 八、超期未执行的处理逻辑

### 场景

```
1月15日  销售填了跟进记录，下次跟进时间设为 1月20日
1月20日  系统提醒销售跟进张总，销售没有执行
1月21日  怎么处理？
```

### 状态流转

```
销售填写"下次跟进时间 1月20日"
        ↓
系统自动生成"计划跟进"占位记录  →  状态：待执行
        ↓
1月20日到期
        ↓
销售填了新记录    →  状态：已完成
销售没填         →  状态：未执行（标红，永久保留）
        ↓
1月22日销售填了新记录
        ↓
新记录出现在时间轴顶部
1月20日未执行记录依然存在，不消失
```

### 为什么未执行记录必须保留

> **已计划但未执行的跟进，是有价值的信息，不能被系统自动抹掉。**

它记录了一个真实发生的事：这个客户，有一次计划好的跟进，被销售漏掉了。

```
销售自己    回顾时知道自己曾经漏跟过
主管        复盘时能看到销售的执行情况
公司        积累数据，分析哪类客户容易被忽略
```

### 超期升级提醒

```
超期1天   继续提醒销售本人
超期3天   同时通知组长
超期7天   同时通知总监
```

## 九、入口设计

销售新建跟进记录，有三个场景和三个入口：

### 入口一：客户详情页内

刚和某个客户通话完，进入客户详情页，在跟进记录 Tab 里点"新建"。记录自动关联该客户，不需要再选。

### 入口二：全局快速新建

首页或列表页右上角"+ 新建跟进"按钮，弹出表单，第一个字段是"选择客户"。适合批量录入多个客户。

### 入口三：今日待跟进看板（最高频）

```
今日待跟进
├── 张总  上次跟进 3天前   ⚠️ 超期   [记录跟进]
├── 李总  上次跟进 7天前   ⚠️ 超期   [记录跟进]
└── 王总  计划今日跟进              [记录跟进]
```

点击"记录跟进"直接弹出填写窗口，客户已自动关联。阻力最小，使用频率最高。

### 弹窗 vs 新页面

优先用弹窗，必填字段控制在5个以内。字段非常多或需要上传大量附件时才用新页面。

## 十、页面导航结构

```
左侧导航栏（或底部Tab）
├── 首页 / 工作台       ← 默认落地页
├── 客户管理
├── 跟进记录
├── 销售管理
└── 数据报表
```

**首页/工作台的定位：今天我要做什么**

```
首页
├── 今日待跟进客户        最核心，放最上面
├── 我的客户概览          总客户数、本月新增
├── 待办提醒              到期任务、超期未跟进
└── 业绩进度              本月目标完成进度
```

销售打开系统，30秒内知道今天要干什么。

## 十一、功能优先级

| 优先级 | 功能 |
|-------|------|
| P0 必须有 | 新建记录、客户关联、实际跟进时间、下次跟进时间、跟进时间轴、今日待跟进看板、基础提醒 |
| P1 重要 | 超期提醒、计划未执行记录保留、修改日志、语音录入转写、AI 提取摘要标题 |
| P2 有了更好 | AI 结构化字段提取、附件上传、快速跟进、团队动态 |
| P3 锦上添花 | AI 分析客户意向变化、AI 推荐下一步行动、AI 自动生成管理周报 |

这个优先级的核心判断是：

```
P0 先保证跟进闭环能跑起来
P1 再解决数据可信和录入降本
P2 做结构化沉淀和管理增强
P3 才进入智能分析和决策辅助
```

## 十二、产品迭代路径

```
第一版   手动打字填写，跑通新建记录、客户关联、时间轴、今日待跟进和基础提醒
第二版   增加超期提醒、未执行计划保留、修改日志，保证数据可信
第三版   支持语音录入，自动转文字，并由 AI 自动生成摘要标题
第四版   AI 结构化提取客户反馈、价格意向、竞品信息、待办事项和下次跟进
第五版   AI 分析所有记录，识别客户意向变化，并推荐下一步行动
```

## 十三、关键设计决策汇总

| 决策点 | 推荐做法 | 原因 |
|-------|---------|------|
| 跟进时间用哪个？ | 允许手动填写实际发生时间 | 销售往往事后补录，系统时间失真 |
| 挂哪个层级？ | 客户必填，联系人选填 | 平衡精细度与填写负担 |
| 时间轴 vs 列表？ | 详情页用时间轴，报表用列表 | 各自适合不同场景 |
| 提醒归谁？ | 跟着客户负责人走，非原始填写人 | 客户转移后提醒也应转移 |
| 能否修改历史记录？ | 允许修改，但保留修改日志 | 兼顾纠错需求和数据真实性 |
| 能否删除记录？ | 销售不能删，只能改；管理员可删 | 防止销售删除不好看的记录 |
| 未执行计划如何处理？ | 永久保留，标红显示 | 已计划未执行是有价值的信息 |
| 摘要标题谁来写？ | AI 自动生成，销售确认 | 降低填写负担，保证数据质量 |

## 十四、AI 原生 CRM 的完整图景

当前设计的语音转文字+结构化跟进记录，解决的是**录入环节**的问题，是整个 AI 原生 CRM 最重要的地基。

数据进来之后，AI 还能介入更多环节：

**销售执行层**
```
现在做的   语音转文字 + 结构化跟进记录
未来可做   AI 分析客户意向变化趋势
           AI 提醒"这个客户30天没有实质进展，建议换策略"
           AI 根据历史记录推荐下一步行动
```

**管理层**
```
未来可做   AI 自动生成销售周报
           AI 识别哪些客户有流失风险
           AI 分析哪个销售的跟进方式成单率最高
```

**客户洞察层**
```
未来可做   AI 跨多条记录分析客户的真实顾虑
           AI 对比同类客户成交路径，给出建议
```

> 录入环节是最基础、最关键的一步。数据不进来，后面所有的 AI 分析都是空谈。从这里开始，方向完全正确。

## 十五、核心结论

| 维度 | 核心结论 |
|------|---------|
| 本质 | 销售行为的结构化日志 |
| 最高频操作 | 新建一条跟进记录 |
| 传统最大矛盾 | 数据质量和填写负担不可兼得 |
| AI 解决了什么 | 把数据质量和填写负担解耦 |
| 最重要的入口 | 今日待跟进看板 |
| 最容易忽视的数据 | 计划跟进但未执行的记录 |
| 推行失败的根本原因 | 只站在公司角度设计，忽视了销售的诉求 |

> **跟进记录能不能真正跑起来，70% 取决于管理方式，30% 取决于产品设计。产品可以降低阻力、提供激励，但如果管理层把 CRM 当监控工具用，销售的抵制是任何产品设计都解决不了的。**

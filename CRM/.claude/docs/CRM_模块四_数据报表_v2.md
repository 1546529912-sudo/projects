# CRM 模块四：数据报表 v2

> 学习路径：✅ 模块一：客户管理 → ✅ 模块二：跟进记录 → ✅ 模块三：销售管理 → ⏭ **模块四：数据报表（当前）** → ⬜ 模块五：系统设置

---

## 一、是什么？

前三个模块解决的是：
- 模块一：**客户是谁**
- 模块二：**跟进了什么**
- 模块三：**生意谈得怎么样**

模块四要解决的是：

> **这些数据加在一起，说明了什么问题？**

数据报表不产生新数据，它是对前三个模块数据的**汇总、分析、可视化**。管理层靠它做决策，销售员靠它看自己的业绩。

---

## 二、报表的使用者是谁？

不同角色看报表的目的完全不同：

| 角色 | 看什么 | 目的 |
|------|--------|------|
| 销售员 | 自己的业绩、商机进度 | 知道自己完成了多少，还差多少 |
| 销售主管 | 团队整体数据、每个人的表现 | 发现问题，及时辅导 |
| 管理层/总监 | 全公司漏斗、收入趋势 | 判断业务健康度，做战略决策 |

**设计关键点：同一张报表，不同角色看到的数据范围不同**——和模块一的数据权限体系打通，销售员只看自己的，主管看团队的。

---

## 三、四类核心报表概览

| 报表 | 回答的问题 | 核心价值 |
|------|-----------|---------|
| 销售漏斗 | 商机在各阶段的分布和流转 | 找到销售过程的卡点 |
| 业绩完成 | 目标完成了多少，预计能完成多少 | 提前预警，及时干预 |
| 客户来源分析 | 哪个渠道带来的客户最值钱 | 指导市场预算分配 |
| 销售员效能 | 每个销售员的工作质量 | 辅导销售，发现问题 |

## 四、销售漏斗报表

### 漏斗统计的是数量还是金额？

**两个都要。**

- 数量反映销售活跃度
- 金额反映业务价值

一个销售手里有50个小商机和5个大商机，数量漏斗和金额漏斗形状完全不同，背后的问题也不同。

### 漏斗的统计单位是商机，不是客户

一个客户可以有多个商机，处于不同阶段：

```
阿里巴巴（一个客户）
├── 商机A   ERP采购      谈判中    155万
└── 商机B   培训服务     方案报价   80万
```

漏斗里这两个商机分别出现在不同阶段，不能合并。

**想看某个客户整体价值，用客户详情页，不是漏斗。**

| 想看什么 | 用什么 |
|---------|--------|
| 销售管道整体健康度 | 漏斗报表（以商机为单位） |
| 某个客户的整体价值 | 客户详情页 |

### 统计口径：快照 vs 流量

**方式一：快照统计（当前状态）**

统计此刻每个阶段有多少商机。

```
现在是3月31日，漏斗显示：
初步接触   20个   ← 现在处于这个阶段的商机
需求确认   15个
方案报价   10个
谈判中      8个
```

优点：简单直观，看当下的pipeline。
缺点：看不出流动趋势。

**方式二：流量统计（阶段经过）**

统计某段时间内，进入过这个阶段的商机数量。

```
本季度，经过各阶段的商机数：
初步接触   100个
需求确认    75个
方案报价    50个
谈判中      30个
赢单        18个
```

优点：能算出每个阶段的转化率，找到卡点。
缺点：同一个商机可能在多个阶段被计算多次。

**推荐做法：两种都提供，默认展示快照，提供切换入口。**

### 转化率怎么算

```
初步接触 → 需求确认  转化率 = 75/100 = 75%
需求确认 → 方案报价  转化率 = 50/75  = 67%
方案报价 → 谈判中    转化率 = 30/50  = 60%
谈判中   → 赢单      转化率 = 18/30  = 60%

整体赢单率 = 18/100 = 18%
```

主管最关心哪个阶段转化率最低——那里就是团队最需要改进的地方。

### 时间维度

漏斗必须限定时间范围：

| 维度 | 含义 | 适用场景 |
|------|------|---------|
| 商机创建时间 | 这批商机是什么时候建的 | 看某个时期开发的商机质量 |
| 预计成交时间 | 这批商机预计什么时候成交 | 预测本季度能完成多少 |
| 阶段推进时间 | 商机是什么时候进入这个阶段的 | 分析销售节奏 |

**推荐：默认按商机创建时间筛选，提供切换。**

### 按产品线切片

漏斗可以按产品线切割，数据来源是模块三系统设置里的产品目录。

**链路：**
```
系统设置 → 产品目录（管理员维护）
    ↓ 销售填报价单时从目录选产品
报价单（挂在商机下）
    ↓
漏斗报表按产品线切片
```

**一个商机包含多个产品时，按产品拆分金额统计：**

```
商机：阿里巴巴ERP项目  总金额155万
├── ERP软件授权   80万  → 计入ERP软件授权漏斗
├── 实施服务      60万  → 计入实施服务漏斗
└── 售后维保      15万  → 计入售后维保漏斗
```

**注意：** 下钻时要展示商机总价和产品明细，让管理者清楚这80万是155万商机里的一部分，不是一笔独立的生意。

**产品目录可按产品线（大类）归类：**

产品线差异很大时，不按单个产品切，而是按产品线：

```
产品线：企业软件
├── ERP软件授权
├── 实施服务
└── 售后维保
```

商机整体归入这条产品线，报表更清晰。第一版用主产品归类（销售创建商机时选一个主产品），后期再升级。

### 异常识别

好的漏斗报表要主动告诉管理者哪里有问题：

```
异常一：漏斗倒置
方案报价  50个
谈判中    70个  ← 比上一阶段多
说明：有商机被跳级推进，或者数据录入有问题

异常二：某阶段堆积
需求确认  80个  ← 太多了
方案报价  10个
说明：需求确认→方案报价卡住了，可能是报价能力不足

异常三：长期未推进
谈判中有15个商机，其中8个超过60天没有更新
说明：这些可能是僵尸商机，需要主管介入
```

### 下钻能力

```
漏斗图：谈判中  30个商机
    ↓ 点击
商机列表：展示这30个商机的详情
    ↓ 点击某一个
商机详情页：看完整的跟进历史
```

从宏观异常，一路下钻到具体问题。

### 设计决策汇总

| 决策点 | 推荐做法 |
|--------|---------|
| 统计单位 | 商机，不是客户 |
| 统计口径 | 快照+流量都提供，默认快照 |
| 统计维度 | 数量+金额都要 |
| 时间维度 | 默认按创建时间，可切换 |
| 产品切片 | 第一版按主产品归类，后期升级 |
| 异常识别 | 主动标注，不只展示数字 |
| 下钻能力 | 从漏斗能钻到具体商机 |
| 第一版 | 快照+数量+金额，切片和异常识别是第二版 |

## 五、业绩完成报表

### 业绩节点的定义

成交金额算哪个时间点，直接影响报表逻辑：

```
1月15日  签合同   155万
2月10日  到账     100万（首款）
4月30日  到账      55万（尾款）
```

| 节点 | 问题 |
|------|------|
| 签合同日 | 客户可能退款，业绩虚高 |
| 首款到账日 | 分期付款尾款怎么算 |
| 全款到账日 | 周期太长，销售员等不起 |
| 按回款比例 | 最准确，但最复杂 |

**推荐：按回款到账算，分期的按每笔到账分别计入。** 和模块三"赢单≠已成交"保持一致。

### 目标从哪里来

目标在系统设置里录入，分两个层级：

```
团队目标  本季度  500万
    ↓ 拆解
个人目标
├── 张三   150万
├── 李四   150万
└── 王五   200万
```

个人目标加总不强制等于团队目标，但系统会提示差异：

```
⚠️ 个人目标合计 550万，超出团队目标 500万 10%
```

### 预测金额怎么算

按商机阶段给默认赢率，加权求和：

```
初步接触   ×10%
需求确认   ×25%
方案报价   ×50%
谈判中     ×75%
```

计算示例：

```
商机A  谈判中   155万 × 75% = 116万
商机B  方案报价  80万 × 50% =  40万
商机C  需求确认  60万 × 25% =  15万
─────────────────────────────────
预测金额合计：171万
```

第一版用默认赢率，后期根据历史数据反推更准确的赢率。

### 时间进度对比

完成率要结合时间进度来看：

```
时间已过去  69%（本季度第二个月末）
业绩完成    64%

结论：业绩进度落后于时间进度，需要关注
```

### 下钻路径

```
团队完成率  98%
    ↓ 点击
各销售员完成情况
    ├── 张三  150万目标  完成120万  80%
    ├── 李四  150万目标  完成45万   30%  ⚠️
    └── 王五  200万目标  完成155万  77%
    ↓ 点击李四
李四的商机列表
    ├── 在途商机：3个，预测+80万
    └── 本季度已输单：5个
    ↓ 点击某个输单商机
输单原因：价格太高，客户选了竞品
```

### 设计决策汇总

| 决策点 | 推荐做法 |
|--------|---------|
| 业绩节点 | 按回款到账，分期按每笔计入 |
| 目标录入 | 系统设置里按团队+个人分别设置 |
| 预测算法 | 第一版用阶段默认赢率，后期用历史数据反推 |
| 进度展示 | 完成率+时间进度对比，两个结合才有意义 |
| 异常提醒 | 主动标注落后的销售员 |
| 下钻路径 | 从完成率→个人→商机→输单原因 |

## 六、客户来源分析报表

### 这张报表要回答什么

```
市场部：我们投了这么多渠道，哪个渠道最值钱？
管理层：明年预算怎么分配？
销售主管：哪个渠道来的客户最好成交？
```

数据来源：模块一的线索来源字段 + 模块三的成交金额，两个模块打通才能出这张表。

### 完整链路

来源标签从线索创建时就打上，之后一路继承：

```
线索进入CRM（打上来源标签）
    ↓
转化为客户（客户继承来源标签）
    ↓
创建商机（商机继承来源标签）
    ↓
赢单成交
    ↓
报表统计该渠道的贡献
```

来源标签只打一次，后面自动继承，不需要重复填。

### 核心数据

```
渠道          线索数   转化客户数   转化率   成交数   成交金额
微信广告       300      45          15%      15      120万
展会            80      30          38%      12      200万
百度广告       500      20           4%       5       30万
老客户推荐      20      18          90%      14      150万
```

### 最有价值的发现：线索量多 ≠ 质量好

```
百度广告   500条线索  →  成交5个   成交金额30万
老客户推荐  20条线索  →  成交14个  成交金额150万
```

百度带来的线索是老客户推荐的25倍，但成交金额只有1/5。这个发现会直接影响市场预算分配。

### 转化率漏斗

以展会渠道为例：

```
线索数      80个
转化客户    30个   转化率38%
创建商机    28个   商机率93%
进入谈判    20个   推进率71%
最终赢单    12个   赢单率60%
```

每一层断点背后的原因不同：

| 断点 | 说明 |
|------|------|
| 线索→客户转化率低 | 线索质量差，广告受众定向有问题 |
| 客户→商机率低 | 销售员没有认真跟进 |
| 商机→赢单率低 | 谈判能力有问题，或竞争激烈 |

### 归因方式

**核心问题：一个客户接触了多个渠道，成交算谁的功劳？**

```
张三  1月通过百度广告留资   →  线索A  来源=百度广告
      2月参加展会扫码       →  线索B  来源=展会
      3月老同事推荐         →  线索C  来源=老客户推荐
      4月成交了150万
```

三种归因方式：

| 归因方式 | 统计结果 | 适合场景 | 主要问题 |
|---------|---------|---------|---------|
| 首次来源 | 百度广告 +150万 | 关注是什么渠道带来了流量 | 忽略后续渠道的临门一脚 |
| 最后来源 | 老客户推荐 +150万 | 关注是什么渠道促成了决策 | 忽略前期渠道的铺垫 |
| 线性归因 | 三个渠道各 +50万 | 全面评估每个渠道贡献 | 计算和理解成本高 |

**三种方式都有缺陷，没有完美答案。** 客户的购买决策是多个触点共同影响的结果，任何单一归因方式都无法100%还原真相。

大公司的做法是同时跑多种归因模型对比结论，但这需要足够的数据量和分析能力。

**第一版务实做法：用首次来源，最简单可靠。**

### 多来源数据从哪里来？

**来源记录在线索合并时由系统自动生成，不是销售员手动填的。**

```
销售员A  1月录入张三  来源=百度广告  →  线索A
销售员B  2月录入张三  来源=展会      →  线索B
              ↓
管理员合并两条线索
              ↓
系统自动保留两条来源记录：
├── 百度广告  2026-01-15  （来自线索A）
└── 展会      2026-02-10  （来自线索B）
```

**为什么要把两条来源都保留？**

保留了才有选择权。数据收集和归因计算是分开的：

```
合并时  →  两条来源记录都保留，不丢弃
报表里  →  再决定用哪种归因方式统计
```

丢掉了某条来源，就永远只能用一种归因方式，失去了后期升级的可能。

**销售员手动录入线索时，来源字段保持单选：**

销售员录入线索只填当下这次的来源，查重机制会拦住重复录入，所以多来源几乎不来自销售员手动操作。

### 时间维度的陷阱

**成交数据存在3-6个月的滞后。**

```
1月  展会带来80条线索
3月  其中30个转化为客户（平均2个月）
6月  其中12个成交（又过了3个月）
```

如果按成交时间筛选，6月成交的展会客户，其实是1月展会的结果。

```
按成交时间筛选  →  看这个月收了多少钱，来自哪里
按线索创建时间筛选  →  看这批线索最终值多少钱
```

**评估渠道质量，要用线索创建时间。** 否则容易误判某个渠道在某个月效果特别好，实际上只是几个月前的老线索碰巧在这个月成交了。

### ROI

ROI = Return on Investment，投资回报率。简单说就是花了多少钱，赚回来多少。

```
微信广告
├── 投入：10万广告费
├── 带来成交：120万
└── ROI = 120万 ÷ 10万 = 12倍

百度广告
├── 投入：15万广告费
├── 带来成交：30万
└── ROI = 30万 ÷ 15万 = 2倍
```

**CRM里的现实问题：** CRM知道成交金额，但不知道每个渠道花了多少钱（广告费在各平台后台管理）。第一版先做"每个渠道带来多少线索、多少成交"，ROI是后期打通广告平台数据之后的事。

### 展示形式

**形式一：汇总表格**（看全局对比）

```
渠道          线索数   转化率   成交金额   人均成交金额
老客户推荐     20      90%      150万      10.7万
展会           80      38%      200万       6.7万
微信广告       300     15%      120万       2.7万
百度广告       500      4%       30万       1.5万
```

**形式二：趋势折线图**（看渠道随时间变化）

能发现渠道效果是在上升还是下滑，及时调整策略。

### 设计决策汇总

| 决策点 | 推荐做法 |
|--------|---------|
| 核心指标 | 线索数、转化率、成交金额、人均成交金额 |
| 归因方式 | 第一版用首次来源；后期可同时跑多种模型对比 |
| 来源数据收集 | 合并线索时系统自动保留所有来源，不丢弃 |
| 时间维度 | 按线索创建时间筛选，不是按成交时间 |
| 展示形式 | 汇总表格+趋势折线图结合 |
| 最有价值的发现 | 线索量多≠质量好，要看全链路转化率 |
| 第一版 | 做汇总表格，折线图是第二版 |

## 七、销售员效能报表

### 为什么这张报表最敏感

前三张报表看业务数据，这张报表直接看**人**。

设计不好会有两个问题：
- 销售员觉得被监视
- 销售员为了数据好看开始刷数据（创建没价值的跟进记录，乱推商机阶段）

**核心设计原则：用来发现问题、辅导销售，不是用来惩罚人。**

### 两类指标

**过程指标：销售员做了什么**

```
新增线索数      这个人在主动开发客户吗？
跟进次数        跟进频率够不够？
新建商机数      发现机会的能力怎么样？
商机推进次数    有没有在推动商机往前走？
```

**结果指标：销售员做出了什么**

```
成交金额        最终产出
赢单率          谈判能力
平均成交周期    效率高不高？
客单价          在跟大客户还是小客户？
```

### 只看结果指标有什么问题

```
张三  成交金额 45万  ← 看起来一般
李四  成交金额 20万  ← 看起来很差
```

加上过程指标和客户结构后：

```
张三  负责30个中小客户  跟进120次  平均客单价1.5万
     → 很勤快但客单价低，需要调整客户结构

李四  负责3个大客户     跟进40次   平均客单价6.7万
     → 跟进次数少是正常的，大客户决策周期长
```

结论完全不同。效能报表不能只看单一指标，要结合多个维度。

### 指标链路

把指标串成一条链，哪个环节断了，问题就在哪里：

```
线索数
    ↓  线索转化率
客户数
    ↓  商机创建率
商机数
    ↓  赢单率
成交数
    ↓  客单价
成交金额
```

| 断点 | 说明 |
|------|------|
| 线索多但客户少 | 跟进不及时，或线索质量差 |
| 客户多但商机少 | 发现机会的能力弱，不会挖掘需求 |
| 商机多但赢单少 | 谈判能力有问题，或报价没有竞争力 |
| 赢单多但金额低 | 在跟小客户，需要升级客户结构 |

### 对比基准

**对比方式一：和团队平均值对比**

```
指标          张三    团队平均   对比
跟进次数      85      60        +42% ✅
新建商机       8       7        +14% ✅
赢单率        38%     45%        -7% ⚠️
平均成交周期  23天    20天       +3天 ⚠️
```

**对比方式二：和自己的历史数据对比**

```
张三  赢单率
上季度  42%
本季度  38%  ↓ 在下滑，需要关注
```

和历史对比能发现趋势，避免因团队整体水平低而掩盖个人问题。

### 敏感性的设计处理

**销售员能看到自己的数据**

不能只有主管能看。销售员看到自己的数据，才能自我管理：

```
销售员视角：
我的本月数据
跟进次数    85次    团队排名 2/8
成交金额    45万    目标完成率 75%
待推进商机   3个    其中2个超过14天未更新 ⚠️
```

**团队排名只有主管能看**

不在销售员之间公开展示，避免恶性竞争和抢单。

**异常提醒而不是扣分**

```
❌  差的设计：张三本月跟进次数不达标，扣绩效
✅  好的设计：张三有5个商机超过14天未跟进，建议主管约谈了解情况
```

报表发现问题，处理问题是主管和销售员之间的沟通，不是系统直接裁决。

### 设计决策汇总

| 决策点 | 推荐做法 |
|--------|---------|
| 核心原则 | 用来辅导人，不是惩罚人 |
| 指标类型 | 过程指标+结果指标结合看 |
| 对比基准 | 团队平均值+自己的历史数据 |
| 数据可见性 | 销售员能看自己的，排名只有主管看 |
| 异常处理 | 系统提醒，人来判断，不自动裁决 |
| 第一版核心 | 成交金额+目标完成率，其他逐步添加 |

## 八、通用设计决策

### 实时 vs 定时刷新

| 方案 | 优点 | 缺点 |
|------|------|------|
| 实时计算 | 数据最新 | 数据量大时很慢，消耗资源 |
| 定时刷新（如每小时） | 稳定快速 | 数据有延迟 |

**推荐：核心指标实时，复杂报表定时刷新（每天凌晨跑一次）。**

### 导出权限

```
销售员     ❌ 不能导出
销售主管   ⚠️ 仅本部门数据+需要审批
管理员     ✅ 可以导出全部
```

### 功能优先级

| 优先级 | 功能 |
|--------|------|
| P0 必须有 | 销售漏斗、业绩完成进度 |
| P1 重要 | 客户来源分析、销售员效能报表 |
| P2 有了更好 | 自定义报表、数据导出 |
| P3 看情况 | AI预测、BI工具对接、多归因模型对比 |

## 九、核心结论

| 维度 | 核心结论 |
|------|---------|
| 本质 | 对前三个模块数据的汇总与可视化，不产生新数据 |
| 最重要的报表 | 销售漏斗——反映销售过程健康度 |
| 统计单位 | 漏斗以商机为单位，不是客户 |
| 数据权限 | 和模块一打通，不同角色看不同范围 |
| 时间陷阱 | 评估渠道质量按线索创建时间，不是按成交时间 |
| 归因本质 | 没有完美归因，第一版用首次来源，关键是把来源数据收集完整 |
| 效能报表原则 | 用来辅导人，不是惩罚人 |
| 第一版核心 | 漏斗+业绩完成，其他都是配套 |
| 最容易踩的坑 | 报表数据和业务数据不一致，根因是字段定义不统一 |

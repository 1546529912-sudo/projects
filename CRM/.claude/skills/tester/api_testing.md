# 接口验收方法 — CRM项目

## 适用场景
测试Agent收到开发Agent的 MODULE_COMPLETE 后，对后端接口进行验收时使用。

---

## 验收原则

1. **对照接口规范，逐条核对**：参见 architect/api_design.md
2. **每个接口必须测试正常路径和异常路径**
3. **打回必须说清楚：接口路径、请求参数、实际响应、期望响应**

---

## 验收顺序

1. 接口格式规范 → 2. 正常路径 → 3. 异常路径 → 4. 权限控制 → 5. 性能基准

---

## 第一项：接口格式规范

对每个接口检查：

- [ ] 接口路径包含 `/api/v1/`
- [ ] HTTP方法与规范一致（GET/POST/PATCH/DELETE）
- [ ] 响应结构包含 `code` / `message` / `data` 三个字段
- [ ] 成功时 `code` 为 0
- [ ] 失败时 `code` 为对应业务错误码（非0）
- [ ] 列表接口响应中包含 `pagination` 对象（`page` / `page_size` / `total` / `total_pages`）

---

## 第二项：正常路径验收

### 客户管理接口验收用例

**GET /api/v1/customers（列表）**
```
测试用例：
1. 无任何参数，返回默认分页（第1页，20条）
2. 传 page=2&page_size=10，返回第2页10条数据
3. 传 keyword=张，只返回名称包含"张"的客户
4. 传 status=active，只返回该状态客户
5. 传 owner_id={当前用户ID}，只返回该销售员的客户

期望响应：
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [...],
    "pagination": {
      "page": 1, "page_size": 20, "total": 56, "total_pages": 3
    }
  }
}
```

**POST /api/v1/customers（新建）**
```
测试用例：
1. 传完整必填字段，返回新建成功的客户对象（包含id和created_at）
2. 确认响应中没有多余字段（不返回数据库内部字段如password_hash）

期望响应：
{ "code": 0, "message": "success", "data": { "id": 123, ... } }
```

**PATCH /api/v1/customers/{id}（更新）**
```
测试用例：
1. 只传要修改的字段，其他字段不变
2. 修改成功后，响应返回更新后的客户数据
3. updated_at 已更新为当前时间
```

**DELETE /api/v1/customers/{id}（删除）**
```
测试用例：
1. 删除存在的客户，返回 204 No Content
2. 被删除的客户在列表中消失
3. 但数据库中 is_deleted=1（软删除，数据保留）
```

## 第三项：异常路径验收

### 必测异常场景

| 场景 | 测试方法 | 期望响应 |
|---|---|---|
| 缺少必填参数 | 不传 name 字段新建客户 | code非0，errors数组指出字段 |
| 参数格式错误 | phone传"abc123" | code=40002，message说明格式错误 |
| 资源不存在 | GET /customers/99999 | HTTP 404，code非0 |
| 重复数据 | 两次新建同名客户 | HTTP 409，code=20002 |
| 无效分页参数 | page=-1 或 page_size=999 | 返回错误或使用默认值（需与规范一致）|
| 空搜索关键词 | keyword=（空字符串）| 返回全部数据，不报错 |

### 必测安全场景

| 场景 | 测试方法 | 期望响应 |
|---|---|---|
| 未携带token | 不带Authorization头请求任意接口 | HTTP 401 |
| token已过期 | 使用过期token请求 | HTTP 401，code=10001 |
| 无效token | Authorization: Bearer invalid_token | HTTP 401 |
| 访问他人数据 | 销售员A访问销售员B的私有客户 | HTTP 403，code=10002 |

## 第四项：权限控制验收

针对每个接口，验证以下角色的权限是否正确：

| 接口 | 管理员 | 销售主管 | 销售员 |
|---|---|---|---|
| 查看所有客户 | ✓ | ✓（本团队）| ✗（只看自己）|
| 查看客户详情（他人的）| ✓ | ✓（本团队）| ✗ |
| 新建客户 | ✓ | ✓ | ✓ |
| 删除客户 | ✓ | ✓ | ✗ |
| 分配客户给他人 | ✓ | ✓ | ✗ |
| 查看所有人报表 | ✓ | ✓ | ✗ |
| 用户管理 | ✓ | ✗ | ✗ |

**验收方法：** 用不同角色的账号分别调用接口，确认权限控制正确。

---

## 第五项：性能基准验收

**基准要求（第一版，数据量小的情况下）：**
- 列表接口响应时间：< 500ms
- 详情接口响应时间：< 200ms
- 新建/更新接口响应时间：< 300ms

**验收方法：** 使用浏览器开发者工具Network面板查看接口响应时间。

如果接口超过基准，检查：
1. 是否有N+1查询问题（循环内查询数据库）
2. 是否缺少索引（新建的查询没有对应索引）
3. 是否返回了过多不必要的字段

---

## 接口打回格式要求

```
问题编号：API-001
接口：POST /api/v1/customers
问题描述：新建客户不传name字段时，接口返回500而不是400
请求参数：{ "phone": "13800138000" }
实际响应：HTTP 500, { "code": 50001, "message": "服务器内部错误" }
期望响应：HTTP 400, { "code": 40001, "message": "客户名称不能为空", "errors": [{ "field": "name", "message": "不能为空" }] }
严重程度：高（暴露了服务器内部错误，且参数校验缺失）
```

---

## 通过标准

以下情况才能对接口模块输出 TEST_PASS：

- [ ] 所有正常路径按规范返回正确格式
- [ ] 所有必测异常场景正确处理（不返回500）
- [ ] 所有权限控制按角色正确生效
- [ ] 未登录/token过期统一返回401
- [ ] 接口响应时间符合性能基准
- [ ] 响应数据不包含敏感字段（密码、token等）

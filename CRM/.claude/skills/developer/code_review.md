# 代码自检方法 — CRM项目

## 适用场景
开发Agent在输出 MODULE_COMPLETE 之前，对自己写的代码进行自检时使用。

---

## 自检流程

开发Agent完成一个模块后，**按顺序**执行以下检查，全部通过才能输出 MODULE_COMPLETE。

---

## 第一层：功能完整性检查

对照产品Agent输出的功能清单，逐条确认：

- [ ] 功能清单中该模块的每一条功能都已实现
- [ ] 验收标准中的每一条都已满足
- [ ] 第一版不做的功能确实没有做（不多做）

---

## 第二层：代码质量检查

### 2.1 命名规范

**前端（Vue/React）：**
- 组件文件：PascalCase（`CustomerList.vue`）
- 变量/函数：camelCase（`fetchCustomerList`）
- CSS类名：kebab-case（`customer-list-item`）
- 常量：SCREAMING_SNAKE_CASE（`MAX_PAGE_SIZE`）

**后端（Node/Python/Go 等，按项目选型）：**
- 函数/变量：camelCase（JS）或 snake_case（Python）
- 类名：PascalCase
- 常量：SCREAMING_SNAKE_CASE
- 数据库字段：snake_case

### 2.2 函数规则
- [ ] 每个函数只做一件事
- [ ] 函数超过50行，必须拆分
- [ ] 禁止出现魔法数字（用命名常量替代，如 `MAX_RETRY = 3`）
- [ ] 禁止嵌套超过3层的if/循环

### 2.3 注释规则
- [ ] 不写"是什么"的注释（代码自己说）
- [ ] 只写"为什么"的注释（特殊处理原因、业务规则）
- [ ] 禁止留废弃的注释代码块

---

## 第三层：安全检查

### 前端安全
- [ ] 用户输入展示到页面前已做XSS转义（不使用 v-html / dangerouslySetInnerHTML，除非必要且已做转义）
- [ ] 敏感操作（删除、修改权限）有二次确认
- [ ] 没有在前端存储敏感信息（密码、token明文等）
- [ ] API请求携带Authorization头，不在URL中传token

### 后端安全
- [ ] 所有SQL查询使用参数化查询，禁止字符串拼接SQL
- [ ] 用户输入在进入业务逻辑前已做校验
- [ ] 接口已校验用户权限（不能只靠前端隐藏按钮）
- [ ] 文件上传接口已校验文件类型和大小
- [ ] 日志中不打印密码、token等敏感信息

---

## 第四层：接口规范检查

对照架构Agent输出的接口规范逐条核对：

- [ ] 接口路径与规范一致（包括版本号 `/api/v1/`）
- [ ] HTTP方法与规范一致
- [ ] 请求参数与规范一致（字段名、类型、必填）
- [ ] 响应格式符合统一规范（`code` / `message` / `data`）
- [ ] 错误情况返回正确的错误码
- [ ] 分页接口返回了 `pagination` 对象

---

## 第五层：UI规范检查

对照设计Agent输出的设计规范逐条核对：

- [ ] 颜色值与 color_system.md 一致，不自定义新颜色
- [ ] 字体大小与 component_spec.md 一致
- [ ] 间距使用 spacing 变量，不写 margin: 13px 这样的随意值
- [ ] 按钮样式与规范一致
- [ ] 表格样式（行高、边框、表头）与规范一致
- [ ] 空状态和加载状态已处理

---

## 第六层：边界与异常检查

- [ ] 列表为空时有空状态UI（不是空白区域）
- [ ] 网络请求有loading状态
- [ ] 网络请求失败有错误提示（toast/message）
- [ ] 表单提交时已禁用重复提交（防止双击）
- [ ] 数字字段输入了非数字时有提示
- [ ] 超长文字（客户名称极长）不会撑破布局（使用overflow truncate）

---

## 自检报告输出格式

```
模块名称：[模块名]
完成内容：[简述做了什么]
文件路径：[列出主要文件]

自检结果：
  功能完整性：通过 / 不通过（说明哪项未通过）
  代码质量：  通过 / 不通过
  安全检查：  通过 / 不通过
  接口规范：  通过 / 不通过
  UI规范：    通过 / 不通过
  边界处理：  通过 / 不通过

已知遗留问题：[无，或列出不影响主流程的已知问题]
```

所有项通过后才能输出 MODULE_COMPLETE。有任何一项不通过，先修复再自检。
